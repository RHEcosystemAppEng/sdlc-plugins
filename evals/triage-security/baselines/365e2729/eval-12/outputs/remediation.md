Remediate CVE-2026-48901: h2 HTTP/2 CONTINUATION flood. h2 does not limit the
number of CONTINUATION frames following a HEADERS frame, so an attacker can cause
excessive memory allocation and CPU usage (denial of service). The vulnerable
dependency (h2 < 0.4.8) must be updated to the fixed version (0.4.8+).

Affected versions: RHTPA 2.1.0 (h2 0.4.5), RHTPA 2.1.1 (h2 0.4.5)

Fix threshold: < 0.4.8 / fixed 0.4.8, cross-validated from MITRE CVE API
(lessThan 0.4.8) and OSV.dev RUSTSEC-2026-0089 (fixed 0.4.8). The Jira
description gave no precise range.

Upstream fix: https://github.com/hyperium/h2/pull/800
Advisory: https://github.com/advisories/GHSA-2026-r7f2-kk9p

## Implementation Notes

- Target branch: release/0.3.z
- **Dependency type**: to be confirmed. Direct vs transitive could not be determined
  from triage evidence (h2 is commonly pulled in via hyper). Inspect Cargo.lock
  reverse dependencies (`cargo tree -i h2`) first.
- If the vulnerable dependency is dev-only or build-only, the remediation priority
  is Normal regardless of CVE severity. Add the `dev-dependency` label to the task.
- If `release/0.3.z` HEAD already resolves h2 >= 0.4.8, no source change is needed.
  Proceed directly to the downstream propagation task.

### Remediation approach (direct dependency)

- Update h2 dependency to >= 0.4.8 in Cargo.lock / Cargo.toml
- If a direct bump introduces breaking changes, assess whether a code-level
  workaround is viable (see upstream changelog)

### Remediation approach (transitive dependency)

**Preferred: bump the direct dependency**
- Identify the direct dependency that pulls in h2 (e.g., hyper / reqwest / tonic)
- Bump it to a version whose transitive closure includes h2 >= 0.4.8
  (within semver-compatible 0.4.x, `cargo update -p h2` is likely sufficient)
- Verify the bump does not introduce breaking API changes

**Fallback: pin the transitive dependency directly**
- `cargo add h2@0.4.8` to add as a direct dependency, overriding the transitive
  resolution
- Document why the direct dep bump was not viable in the PR description

## Acceptance Criteria

- [ ] h2 dependency is >= 0.4.8 in Cargo.lock on release/0.3.z
- [ ] No other dependency conflicts introduced
- [ ] Existing tests pass

## Test Requirements

- [ ] Existing test suite passes with the updated dependency

## Dependencies

- Related to: TC-8030 (originating CVE Jira, stream 2.2.x)
