## Ordering rule (applies to every task below)

For each task, in this exact order:
1. `jira.create_issue(...)`
2. **Description digest comment** (`shared/description-digest-protocol.md`):
   a. Re-fetch the stored description: `jira.get_issue(<new-key>, fields=["description"])`. Never hash the string passed to `create_issue`, because Jira normalizes content when it stores it.
   b. Write the returned description to `/tmp/task-desc.md`.
   c. Run `python3 scripts/sha256-digest.py /tmp/task-desc.md` and check the exit code is 0. The output is `sha256-md:<64 hex>` from the MCP/markdown path, or `sha256-adf:<64 hex>` from the REST/ADF path.
   d. Post a **standalone** comment (ADF, single paragraph) whose body is exactly one line:
      `[sdlc-workflow] Description digest: <full tagged digest from step c>`
      Do not add the footnote, extra text, an abbreviated hash, a placeholder, or a stripped tag. This digest comment is separate from the skill's footnoted comments.
3. Only after the digest is posted, create that task's issue links.
4. Only after all tasks' links exist, post the summary comments (task list, cross-stream, post-triage).

No actual digest values appear here. They can only be computed from the description
Jira returns after creation, and the protocol forbids example or placeholder hashes.
