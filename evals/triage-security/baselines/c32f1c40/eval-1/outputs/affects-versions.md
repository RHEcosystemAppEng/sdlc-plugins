# Step 3 — Affects Versions Correction

## 3.1 — Discover Available Jira Versions

The available Jira versions would be discovered dynamically by calling:

```
jira.getJiraIssueTypeMetaWithFields(
  projectIdOrKey: "TC",
  issueTypeId: "10024"
)
```

The response would be filtered by the Jira version prefix **RHTPA** to exclude
unrelated versions. Version names from the supportability matrix are used as the
reference (not hardcoded Jira version IDs); the actual Jira version IDs would be
looked up at runtime from the `allowedValues` array.

## 3.2 — Compare and Correct Affects Versions

### Scope

The issue has stream suffix `[rhtpa-2.2]` and is **scoped to the 2.2.x stream**.
Only versions belonging to the 2.2.x stream are included in the correction.
The 2.1.x versions (2.1.0, 2.1.1) are affected but belong to a sibling issue's
scope and are excluded from this correction.

### Comparison

The PSIRT-assigned Affects Versions are incorrect:

| | Versions |
|---|---|
| **Current (PSIRT-assigned)** | RHTPA 2.0.0 |
| **Proposed (lock-file-verified)** | RHTPA 2.2.0, RHTPA 2.2.1, RHTPA 2.2.2 |

**Reason**: PSIRT assigned "RHTPA 2.0.0" which does not correspond to any version
in the supportability matrix. Lock file analysis at pinned commits from the
security matrix confirms that versions 2.2.0, 2.2.1, and 2.2.2 ship quinn-proto
versions within the affected range (< 0.11.14). Versions 2.2.3 and 2.2.4 ship
quinn-proto 0.11.14, which is the fixed version, and are therefore excluded.

### Proposed Jira Mutation

After engineer confirmation, the following update would be performed:

```
jira.edit_issue("TC-8001", fields={
  "versions": [
    {"id": "<RHTPA-2.2.0-jira-id>"},
    {"id": "<RHTPA-2.2.1-jira-id>"},
    {"id": "<RHTPA-2.2.2-jira-id>"}
  ]
})
```

The Jira version IDs (`<RHTPA-2.2.0-jira-id>`, etc.) would be resolved from the
`allowedValues` discovered in Step 3.1. Version names (RHTPA 2.2.0, RHTPA 2.2.1,
RHTPA 2.2.2) are referenced from the supportability matrix rather than hardcoded
Jira version IDs (Important Rule 6).

### Proposed Correction Comment

A comment documenting the correction would be posted to TC-8001:

```
Corrected Affects Versions: [RHTPA 2.0.0] -> [RHTPA 2.2.0, RHTPA 2.2.1, RHTPA 2.2.2].
Based on lock file analysis at pinned commits from security-matrix.md.
Scoped to stream 2.2.x per issue suffix [rhtpa-2.2].
```

No ProdSec Jira account ID is configured in Security Configuration, so no @mention
is included in the correction comment.
