# Step 2.3.5 -- Feature-Gated Dependency: VEX Justification Prompt

## Dependency Scope Decision Tree Result

The dependency scope analysis in Step 2.3.5 identified `rustls` as a **feature-gated optional dependency**:

- **Library**: rustls
- **Feature flag**: `tls-rustls`
- **Feature flag status**: non-default (not included in `default = ["tls-native"]`)
- **Declaration**: `rustls = { version = "0.23.4", optional = true }` in `[dependencies]`
- **Implication**: rustls is not compiled into the production binary when using default features. The product ships with `tls-native` enabled, which uses `native-tls` instead of `rustls`.

Per the dependency scope decision tree in `version-impact-analysis.md`, feature-gated optional dependencies behind non-default feature flags require a user decision before proceeding with remediation.

## VEX Justification Prompt

The following prompt is presented to the engineer:

---

The vulnerable dependency `rustls` is gated behind the `tls-rustls` feature, which is not enabled by default. Recommended VEX justification: **Vulnerable Code not in Execute Path**.

Options:
1. **Skip remediation** -- apply VEX justification and close as not affected
2. **Proceed with remediation** -- create tasks despite the feature gate

Choose (1/2):

---

## Option 1: Skip Remediation

If the engineer chooses option 1:

- The VEX Justification custom field (`customfield_12345`) is set to **Vulnerable Code not in Execute Path** on the Vulnerability issue TC-8051.
- The issue is closed as Not a Bug (not affected) with resolution "Not a Bug".
- A comment is posted documenting the justification:

  > "Closing as not affected. The vulnerable dependency `rustls` is an optional dependency gated behind the non-default `tls-rustls` feature flag. The product ships with `default = ["tls-native"]` -- rustls is not compiled into or executed by the default build. VEX justification: Vulnerable Code not in Execute Path."

- No remediation tasks are created for any version.
- The `ai-cve-triaged` label is added to TC-8051.
- The Comment Footnote is appended to all Jira comments:

  ---
  This comment was AI-generated by [sdlc-workflow/triage-security](https://github.com/RHEcosystemAppEng/sdlc-plugins) v0.13.10.

## Option 2: Proceed with Standard Remediation

If the engineer chooses option 2:

- Standard remediation tasks are created without any label or priority modifications (no `dev-dependency` label, no priority override).
- Since rustls is a source dependency (Cargo ecosystem), **two tasks** would be created per affected stream:
  1. **Upstream backport task** (or dependency bump if upstream fix is already available): bump rustls to >= 0.23.5 in the backend repository on branch `release/0.4.z`
  2. **Downstream propagation subtask**: update the backend source reference in the Konflux release repo (rhtpa-release.0.4.z)

- Both tasks are linked to TC-8051 via "Depend" link type.
- The downstream subtask is blocked by the upstream task via "Blocks" link type.
- Standard labels apply: `["ai-generated-jira", "Security", "CVE-2026-99002"]`
- Task descriptions follow `task-description-template.md` format.
- Description digest comments are posted per `shared/description-digest-protocol.md` before creating issue links.

## Key Observations

- The VEX justification prompt is specific to **feature-gated optional dependencies behind non-default features**. It does not apply to dev-only dependencies (which get the `dev-dependency` label and Normal priority override instead) or to production dependencies.
- The recommended VEX justification "Vulnerable Code not in Execute Path" accurately reflects that rustls code is present in the dependency graph but never compiled into or executed by the default product build.
- This decision applies to all versions in the 2.2.x stream uniformly, since the feature gate configuration is the same across all versions (2.2.0 through 2.2.4).
- If the engineer has evidence that specific customers or deployments enable the `tls-rustls` feature, they should choose option 2 to create remediation tasks despite the non-default feature gate.
