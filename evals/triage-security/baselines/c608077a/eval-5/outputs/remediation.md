## Repository

rhtpa-release.0.4.z

## Target Branch

main

## Description

Remediate CVE-2026-40215: update openssl-libs to 3.0.7-28.el9_4.

openssl-libs versions before 3.0.7-28.el9_4 contain a buffer over-read in
X509_verify_cert() (Subject Alternative Name extension length not validated),
allowing a crafted certificate to leak memory or crash the process.
CVSS 7.1 (High).

Affected versions (rpms.lock.yaml at pinned commits):
- RHTPA 2.2.0 (build 0.4.5, v0.4.5): openssl-libs 3.0.7-25.el9_3
- RHTPA 2.2.1 (build 0.4.8, v0.4.8): openssl-libs 3.0.7-27.el9_4
- RHTPA 2.2.2 (build 0.4.9, retag of 2.2.1): openssl-libs 3.0.7-27.el9_4
Not affected: RHTPA 2.2.3 (v0.4.11) and 2.2.4 (v0.4.12) ship openssl-libs 3.0.7-28.el9_4.

Advisory: https://access.redhat.com/errata/RHSA-2026:4021
CVE record: https://www.cve.org/CVERecord?id=CVE-2026-40215

## Implementation Notes

- Package origin: explicit install — openssl-libs is listed in rpms.lock.yaml
  (SBOM verification skipped — cosign not available; classification is from
  rpms.lock.yaml only)
- Update the package version in Dockerfile (dnf install command or package spec)
  / rpms.in.yaml so openssl-libs resolves to >= 3.0.7-28.el9_4
- If lock file exists: regenerate rpms.lock.yaml
- Builds 0.4.11 (2.2.3) and later already resolve openssl-libs 3.0.7-28.el9_4.
  First verify rpms.lock.yaml on main; if it already pins >= 3.0.7-28.el9_4,
  the remaining work is confirming the next 2.2.x build ships it and
  documenting that customers on 2.2.0–2.2.2 must upgrade to 2.2.3+
