## 3.2 – Comparison (scoped to stream 2.2.x)

The issue suffix `[rhtpa-2.2]` scopes TC-8001 to stream **2.2.x**. Only 2.2.x versions
are proposed. The affected 2.1.x versions (2.1.0, 2.1.1) belong to a sibling or companion
issue (Step 4) or to preemptive remediation (Step 8, Case A). They are **not** added here.

| | Affects Versions |
|---|---|
| Current (PSIRT) | `RHTPA 2.0.0` |
| Proposed | `RHTPA 2.2.0`, `RHTPA 2.2.1`, `RHTPA 2.2.2` |

**Diff:** `Current: [RHTPA 2.0.0] → Proposed: [RHTPA 2.2.0, RHTPA 2.2.1, RHTPA 2.2.2]`

Rationale:
- **RHTPA 2.0.0 is wrong.** No 2.0.x stream exists in the Version Streams table or the
  supportability matrix. PSIRT assigned it from scan time, not from dependency analysis.
- **2.2.0** (`v0.4.5`, quinn-proto 0.11.9) and **2.2.1** (`v0.4.8`, 0.11.12) are below 0.11.14.
- **2.2.2** is a backend retag of 2.2.1 (`v0.4.8`), so it is affected by carry-forward.
- **2.2.3** and **2.2.4** ship 0.11.14 and are not affected, so they are excluded.
- Development stream: not determined (Step 2.2). If the dev version turns out to be in
  this stream and affected, its unreleased Jira version would be added.
