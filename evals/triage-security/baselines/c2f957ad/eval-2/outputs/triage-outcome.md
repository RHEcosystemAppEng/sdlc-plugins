# Triage Outcome — TC-8002 (CVE-2026-28940, serde_json)

## Decision

**Case C: no supported versions affected. Recommend closing as "Not a Bug".**

Every supported RHTPA version ships serde_json 1.0.137 or later, which is outside the
affected range `< 1.0.135`. In the 2.2.x stream this issue is scoped to, that means
1.0.138 in 2.2.0–2.2.2 and 1.0.139 in 2.2.3–2.2.4. The 2.1.x stream ships 1.0.137, so it
is also not affected and no cross-stream action is needed. No remediation tasks will be
created.

## VEX Justification

`customfield_12345` is configured, so the issue should be closed with a VEX value.

- Selected value: **Component not Present**.
- Rationale: the skill defaults to "Component not Present" when the lock file analysis shows
  the vulnerable package *version* is not included. serde_json is in `Cargo.lock`, but only
  at patched versions (>= 1.0.137) in every supported release. The vulnerable code,
  unbounded recursion without the 128-level limit, is not shipped in any version.
- Alternative for the engineer to consider: "Vulnerable Code not Present". It also describes
  the situation, since the package is shipped but the vulnerable code path is not. The
  skill's default is kept unless the engineer prefers this one.
