# Step 3 -- Affects Versions Correction

## Step 3.1 -- Jira Version Discovery

Proposed action: call `getJiraIssueTypeMetaWithFields` to discover available Jira versions
matching the prefix `RHTPA`. Version IDs are discovered dynamically at runtime, never
hardcoded.

## Step 3.2 -- Affects Versions Comparison and Correction

### Current vs Proposed

The issue is scoped to stream 2.2.x per the `[rhtpa-2.2]` suffix. Only versions belonging
to this stream are included in the correction.

```
Current:  [RHTPA 2.0.0]
Proposed: [RHTPA 2.2.0, RHTPA 2.2.1, RHTPA 2.2.2]
```

**Rationale:** PSIRT assigned `RHTPA 2.0.0`, which does not correspond to any configured
version stream (there is no 2.0.x stream). Lock file analysis at pinned commits from
security-matrix.md shows that versions 2.2.0, 2.2.1, and 2.2.2 ship quinn-proto in the
affected range (< 0.11.14). Versions 2.2.3 and 2.2.4 ship the fixed version (0.11.14)
and are excluded.

### Proposed Jira Mutation

```
jira.edit_issue("TC-8001", fields={
  "versions": [
    {"id": "<RHTPA-2.2.0-jira-id>"},
    {"id": "<RHTPA-2.2.1-jira-id>"},
    {"id": "<RHTPA-2.2.2-jira-id>"}
  ]
})
```

Version IDs are resolved from the Jira version registry discovered in Step 3.1. Version
names from the supportability matrix are used as references, not hardcoded Jira version IDs.

### Key Points

- The **ProdSec @mention** uses the ProdSec Jira account ID (`557058:prodsec-mock-account-id`)
  extracted from the Security Configuration in Step 0. This is an ADF `mention` node with
  `attrs.id` set to the configured account ID.
- The ProdSec @mention appears **before** the Comment Footnote (the horizontal rule and
  AI-generated attribution).
- If no ProdSec Jira account ID were configured in Security Configuration, the @mention
  would be omitted silently -- the correction comment would still be posted without it.
- Version names reference the supportability matrix (`RHTPA 2.2.0`, `RHTPA 2.2.1`,
  `RHTPA 2.2.2`) rather than hardcoded Jira version IDs.
