## Architecture summary
- The Service Catalog record (`src/catalog/store.py`) is a shared artifact with four writers:
  - registration (onboarding)
  - scheduled sync
  - fallback import
  - on-demand refresh (`POST /api/catalog/refresh`)
- It has two readers: the summary API and the downloadable report.
- Task 1 adds `ownerGroup` once in the shared store:
  - Resolution rule: supplied value > existing value > `unassigned` default on create.
  - A fail-closed guard prevents persisting a record with an empty owner group.
- Task 1 routes all four writers through that store rule and shows the field in both consumers. Per-path tests cover value presence, update preservation, and stable IDs.
- **Scope note:** this is not onboarding-only. TC-9007's acceptance criteria apply to records "after creation or update" and "regardless of how that record was populated". A registration-only change would leave records from sync, fallback import, and refresh without `ownerGroup`, or would wipe it on refresh.
