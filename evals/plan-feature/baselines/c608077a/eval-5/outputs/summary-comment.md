## Architecture summary
One transactional, reversible SeaORM migration (`migration/src/m0002_advisory_status_enum/mod.rs`) does the following:
- creates `advisory_status_enum` with the values New, Analyzing, Fixed and Rejected
- backfills `advisory.status` from the old `status_id` join
- fails closed if any status cannot be mapped
- drops `status_id` and the `advisory_status` table

The `advisory` entity gets a typed `AdvisoryStatus` enum (`DeriveActiveEnum`) and the lookup entity is removed. Consumers that change to read `advisory.status` with no join:
- `AdvisoryService` and the advisory models
- the list endpoint filter, which now returns 400 for an invalid status
- `SearchService`

The ingestion pipeline maps feed status strings to the enum and writes the value directly. Unknown statuses are rejected instead of silently defaulted. The external API response shape does not change. The migration must be tested against a production-sized dataset before deployment.
