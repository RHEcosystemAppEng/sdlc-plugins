## Architecture summary
- One atomic migration, `m0002_advisory_status_enum`, creates `advisory_status_enum`, adds and backfills `advisory.status`, then drops `advisory.status_id` and the `advisory_status` table. If any row cannot be backfilled, the migration fails and rolls back. `down()` is fully reversible.
- The SeaORM `AdvisoryStatus` ActiveEnum replaces the `advisory_status` entity. `AdvisoryService` and the `/api/v2/advisory` list and get endpoints filter on `advisory.status` directly (no join). The response shape is unchanged.
- Advisory ingestion maps feed status strings to the enum and writes them directly, rejecting unknown values instead of defaulting.
- Feature-branch mode was chosen because the migration, the entity and query changes, and the ingestion changes would each break `main` if merged alone.
