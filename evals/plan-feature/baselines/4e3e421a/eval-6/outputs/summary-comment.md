## Architecture summary

The backend gets a new `remediation` domain module in `modules/fundamental`, using the same model/service/endpoints layout as the other modules. It exposes three read-only aggregation endpoints: summary, by-product and a filterable vulnerability list. They are computed with grouped SQL over the existing `sbom_advisory`, `advisory` and `sbom` entities. There are no new tables. The frontend adds typed REST functions and React Query hooks, then a lazy-loaded `/remediation` page built from PatternFly 5 summary cards, a status-by-severity chart, and a server-side filtered, paginated vulnerability table. Workflow mode is **direct-to-main**: the backend endpoints are additive and land first.
