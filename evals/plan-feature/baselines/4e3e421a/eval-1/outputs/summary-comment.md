### Architecture summary
A new `AdvisorySeveritySummary` model and an `SbomService::advisory_severity_summary` method aggregate unique advisory counts per severity. The aggregation is a single grouped `COUNT(DISTINCT advisory.id)` query over the existing `sbom_advisory` join table, with no new tables. A new Axum handler exposes the result at `GET /api/v2/sbom/{id}/advisory-summary`, following the existing `GET /api/v2/sbom/{id}` handler. The handler returns 404 for unknown SBOMs and caches responses for 5 minutes, keyed per SBOM, through the existing tower-http cache configuration. The ingestor (`modules/ingestor/src/graph/advisory/mod.rs`, and SBOM ingestion if it writes advisory links) invalidates affected SBOM cache entries after it commits new advisory links.
