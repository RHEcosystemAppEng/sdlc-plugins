## Architecture summary
The Service Catalog record (src/catalog/store.py) is a shared artifact. It has four writers:
- registration (src/workflows/registration.py);
- scheduled sync (src/workflows/scheduled_sync.py);
- fallback import (src/workflows/fallback_import.py);
- on-demand refresh (src/api/on_demand_refresh.py, POST /api/catalog/refresh).

It has two readers: the summary API (src/api/catalog_summary.py) and the downloadable report (src/reports/catalog_export.py).

The ownerGroup rules live in the shared store helpers, and every writer uses them:
- Required and non-empty. Persisting a blank value fails, so the store fails closed.
- Preserved on update unless a new value is supplied.

Registration collects the value. Sync, fallback import and refresh keep it and must not change population behavior or stable IDs. Both readers display it from the stored record.

Workflow mode: direct-to-main. One implementation task holds every interdependent change, so no atomicity indicators apply.

Changing registration alone would leave three writers that can drop ownerGroup or create records without it: scheduled sync, fallback import and on-demand refresh.
