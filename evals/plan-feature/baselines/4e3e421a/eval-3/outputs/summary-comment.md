### Architecture summary

**Backend:**
- `SbomService::compare` computes the diff on the fly, with no new tables. It loads each SBOM's packages, licenses, and advisories in bulk from the existing `sbom_package`, `package`, `package_license`, and `sbom_advisory` entities, then diffs them in memory keyed by package name. This meets the p95 < 1s target at 2000 packages.
- `GET /api/v2/sbom/compare?left=&right=` returns six categories.
- Unknown IDs return 404 and never an empty diff (fail-closed).

**Frontend:**
- `useSbomComparison` (React Query) feeds a new `/sbom/compare` page. The URL query params are the source of truth, which makes comparisons shareable.
- The page shows six PF5 `ExpandableSection`s with colored count badges and sortable tables. New critical vulnerabilities are highlighted, and tables with more than 100 rows are virtualized.
- Users reach the page from the SBOM list through "Compare selected".
- Export to JSON/CSV happens client-side.
