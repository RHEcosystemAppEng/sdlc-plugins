## Architecture Summary

The feature adds a server-side advisory severity aggregation endpoint to the SBOM module of the trustify-backend service. The implementation follows the existing `model/ + service/ + endpoints/` module pattern:

1. **Model layer**: A new `SeveritySummary` struct encapsulates severity counts (critical, high, medium, low, total).
2. **Service layer**: A new `SbomService::get_advisory_severity_summary` method queries the `sbom_advisory` join table, deduplicates by advisory ID, and aggregates counts by severity level. Supports optional threshold filtering.
3. **Endpoint layer**: A new `GET /api/v2/sbom/{id}/advisory-summary` endpoint with 5-minute `tower-http` caching middleware. Returns 404 for non-existent SBOMs.
4. **Cache invalidation**: The advisory ingestion pipeline (`modules/ingestor/src/graph/advisory/mod.rs`) is modified to invalidate cached advisory-summary responses when new advisories are linked to SBOMs.
5. **Testing**: Integration tests in `tests/api/advisory_summary.rs` verify the endpoint behavior. Cross-cutting smoke tests and performance benchmarks validate end-to-end functionality and latency requirements (p95 < 200ms for 500 advisories).
6. **Documentation**: REST API reference updated with the new endpoint.

No new database tables are required — the implementation uses the existing `sbom_advisory` join table and `advisory` entity.
