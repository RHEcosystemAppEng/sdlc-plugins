## Architecture Summary

The feature adds a server-side advisory severity aggregation endpoint to reduce frontend round-trips for dashboard severity widgets. The implementation follows the trustify-backend module pattern (model + service + endpoints):

1. **Model layer**: new `AdvisorySeveritySummary` struct in the SBOM module
2. **Service layer**: aggregation query on `SbomService` that joins `sbom_advisory` and `advisory` entities, deduplicates by advisory ID, and groups counts by severity level
3. **Endpoint layer**: new Axum handler at `GET /api/v2/sbom/{id}/advisory-summary` with 5-minute `tower-http` cache and optional `?threshold` query parameter
4. **Cache invalidation**: advisory ingestion pipeline extended to invalidate cached summaries when new advisories are linked to SBOMs
5. **Testing**: integration tests in `tests/api/`, smoke tests, and performance benchmarks validating p95 < 200ms for 500 advisories

No new database tables are required — the feature leverages existing `sbom_advisory` and `advisory` entities.
