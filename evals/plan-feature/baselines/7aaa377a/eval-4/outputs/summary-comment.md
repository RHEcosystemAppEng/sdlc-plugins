### Architecture Summary

The license compliance report is implemented as a new capability within the existing SBOM module, following the established model/ + service/ + endpoints/ pattern:

1. **Data model layer** (Task 1): New LicenseReport and LicenseGroup model types, plus a LicensePolicy configuration model loaded from a JSON config file.
2. **Service layer** (Task 2): LicenseReportService queries the existing sbom_package and package_license entities to aggregate license data across the full dependency tree (including transitive dependencies), groups by license type, and checks compliance against the configured policy.
3. **API layer** (Task 3): GET /api/v2/sbom/{id}/license-report endpoint registered under the existing SBOM routes.
4. **Testing** (Task 4): Integration tests covering compliance flagging, transitive dependencies, edge cases, and the p95 < 500ms performance requirement.
5. **Documentation** (Task 5): New content documenting the endpoint and policy configuration for compliance officers.

No new database tables are required — the report aggregates from existing package_license data.
