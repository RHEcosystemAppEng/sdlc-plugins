## trustify-backend

### Changes

- Add license report model types (`LicenseGroup`, `LicenseReport`) in a new `license_report.rs` model file under the SBOM module
- Add license policy configuration model and JSON config file for defining compliant/non-compliant license rules
- Add `LicenseReportService` to aggregate package licenses across the full SBOM dependency tree (including transitive dependencies), group by license type, and check compliance against the configured policy
- Add `GET /api/v2/sbom/{id}/license-report` endpoint that returns the structured compliance report
- Register the new endpoint route in the SBOM endpoints module and ensure it is mounted in `server/src/main.rs`
- Add integration tests for the license report endpoint covering compliant licenses, non-compliant flagging, transitive dependencies, and performance constraints

## Workflow Mode Decision

**Selected mode:** `direct-to-main`

**Rationale:** No atomicity indicators were identified:

1. **Coordinated schema migrations** -- No. The feature explicitly requires no new database tables; it aggregates from existing `package_license` data.
2. **Breaking API changes** -- No. Only a new endpoint is being added (`GET /api/v2/sbom/{id}/license-report`). No existing APIs are modified.
3. **Cross-cutting refactors** -- No. All changes are additive within the existing SBOM module structure.
4. **Tightly coupled feature components** -- No. This is a single-repository, backend-only feature. Each task's PR can land on `main` independently when merged in dependency order (model first, then service, then endpoint, then tests).

All tasks will target `main` as their branch.
