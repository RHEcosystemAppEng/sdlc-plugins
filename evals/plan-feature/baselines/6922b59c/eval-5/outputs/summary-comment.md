## Architecture Summary

This feature replaces the `advisory_status` lookup table with a PostgreSQL enum column (`advisory_status_enum`) directly on the `advisory` table. The change spans four layers:

1. **Database layer** — a reversible migration creates the enum type, adds the column, backfills existing data from the lookup table join, drops the FK column, and drops the lookup table.
2. **Entity layer** — SeaORM entity definitions are updated to use `DeriveActiveEnum` for the new enum type; the `advisory_status` entity is removed.
3. **Service/endpoint layer** — all advisory queries are simplified to read the enum column directly, eliminating the join overhead (~40ms p95 improvement).
4. **Ingestion layer** — the advisory ingestion pipeline writes enum values directly instead of inserting into the lookup table.
