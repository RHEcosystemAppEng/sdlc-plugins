## Architecture Summary

The license compliance report is implemented as a new sub-feature within the existing SBOM domain module, following the established `model/ + service/ + endpoints/` pattern:

1. **Model layer** (Task 1): defines the report data structures (`LicenseReport`, `LicenseReportGroup`) and the policy configuration schema (`LicensePolicy`) with serde serialization support.
2. **Service layer** (Task 2): aggregates package-license data from existing entities (`sbom_package`, `package_license`), walks the transitive dependency tree, groups by license, and evaluates compliance against the configured policy.
3. **Endpoint layer** (Task 3): exposes `GET /api/v2/sbom/{id}/license-report` as an Axum route handler, registered in the SBOM endpoint module.
4. **Testing** (Task 4): integration tests covering compliant, non-compliant, transitive, empty, and error scenarios against a real PostgreSQL test database.
5. **Documentation** (Task 5): new content documenting the endpoint and policy configuration for compliance officers.

No new database tables are required — the report aggregates from existing `package`, `sbom_package`, and `package_license` entities.
