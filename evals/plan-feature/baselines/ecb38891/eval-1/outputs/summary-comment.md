### Architecture Summary

The feature adds a new REST endpoint `GET /api/v2/sbom/{id}/advisory-summary` that aggregates vulnerability advisory severity counts for a given SBOM. The implementation follows the existing module pattern (`model/ + service/ + endpoints/`):

1. **Model layer**: new `AdvisorySeveritySummary` struct in the SBOM module
2. **Service layer**: new `get_advisory_summary` method on `SbomService` that queries the existing `sbom_advisory` join table with advisory deduplication and severity grouping
3. **Endpoint layer**: new Axum handler with 5-minute tower-http cache middleware
4. **Ingestion integration**: cache invalidation hook in the advisory ingestion pipeline
5. **Non-MVP extension**: optional `?threshold` query parameter for severity filtering

No new database tables are required -- the implementation uses the existing `sbom_advisory` relationship table and `advisory` entity.
