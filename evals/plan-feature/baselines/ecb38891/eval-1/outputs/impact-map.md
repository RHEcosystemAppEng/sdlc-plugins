# Repository Impact Map — TC-9001

## Feature: Add advisory severity aggregation endpoint

### trustify-backend

Changes:
- Add `AdvisorySeveritySummary` response model struct in the SBOM module's model layer
- Add `get_advisory_summary` service method to `SbomService` that queries the `sbom_advisory` join table, groups by severity, and deduplicates by advisory ID
- Add `GET /api/v2/sbom/{id}/advisory-summary` endpoint handler with 5-minute cache middleware (tower-http)
- Register the new endpoint route in `modules/fundamental/src/sbom/endpoints/mod.rs`
- Add cache invalidation hook in advisory ingestion pipeline (`modules/ingestor/src/graph/advisory/mod.rs`) to invalidate cached summaries when new advisories are linked to an SBOM
- Add optional `?threshold=critical` query parameter support for severity filtering (non-MVP)
- Add integration tests for the new endpoint in `tests/api/`
- Update REST API documentation to include the new endpoint

### Excluded requirements

None — all requirements from the Feature description can be planned against the trustify-backend repository.

## Workflow Mode Decision

**Selected mode:** `direct-to-main`

**Rationale:** No atomicity indicators were identified:
1. No coordinated schema migrations — the feature explicitly requires no new database tables and uses existing `sbom_advisory` relationship tables.
2. No breaking API changes — this is a purely additive new endpoint; no existing endpoints are modified.
3. No cross-cutting refactors — changes are confined to the SBOM module, advisory ingestion module, and test directory.
4. No tightly coupled frontend-backend changes — this is a backend-only feature; the frontend dashboard team will consume the endpoint independently.

All tasks can be merged to `main` independently without leaving the codebase in a broken state.
