## Architecture summary

Search gets faster because PostgreSQL full-text (GIN/tsvector) indexes are added for the SBOM, advisory and package text columns (T1). `SearchService` then queries those indexes, and the search route uses the existing `tower-http` response caching (T2). Relevance improves by ranking results with exact identifier or name matches first, then by `ts_rank_cd`, which becomes the default sort (T3). Users can narrow results with optional, strictly validated filters for entity type, advisory severity and package license, built on the shared helpers in `common/src/db/query.rs` (T4). Unknown filter values are rejected with 400 and never silently ignored. All changes are backward compatible with the existing `GET /api/v2/search` contract.
