## Architecture summary

All changes stay inside the existing `modules/search` module (`SearchService` + `GET /api/v2/search`) and reuse the shared query helpers in `common/src/db/query.rs`:

- **Performance:** first measure (Task 1), then add expression or generated-column indexes through a new migration (Task 2). Ingestion code does not change.
- **Relevance:** order results by score, with exact identifier matches boosted and a stable tie-breaker for pagination (Task 3).
- **Filtering:** add optional `type`, `severity` and `license` parameters. Invalid values return 400 instead of being silently ignored (Task 4).

The API stays backward compatible: same path, same `PaginatedResults<T>` shape, and all new parameters are optional. Workflow mode is **direct-to-main**.
