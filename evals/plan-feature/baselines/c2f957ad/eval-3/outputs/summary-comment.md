## Architecture summary
- **Backend:** a new `SbomComparison` model (`modules/fundamental/src/sbom/model/comparison.rs`) and `SbomService::compare` compute the diff in memory from existing `sbom_package`, `package_license` and `sbom_advisory` data. No new tables or migrations. A new handler `endpoints/compare.rs` exposes `GET /api/v2/sbom/compare?left=&right=`. It returns 400 for bad parameters and 404 for unknown SBOMs rather than an empty diff. The target is p95 < 1s at 2000 packages per SBOM.
- **Frontend:** typed REST function and `useSbomComparison` React Query hook. The new lazy-loaded `/sbom/compare` page uses PF5 `Select` selectors and six `ExpandableSection` diff sections with colored count badges. Tables are virtualized above 100 rows, and critical new vulnerabilities are highlighted. The `left`/`right` query params drive the page, so comparisons can be shared by URL. A "Compare selected" action on the SBOM list is the entry point. JSON/CSV export runs client-side.
- **Excluded or open items:** the Grafana latency dashboard and timeout alerting are excluded because no observability repository is available. Server-side diff pagination and the "same product" check are open product questions.
