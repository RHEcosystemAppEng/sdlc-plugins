### Architecture summary
- `SbomService` gets a new method that counts DISTINCT advisory IDs per severity from the existing `sbom_advisory` join table, in a single grouped query with no new tables.
- A new handler in `modules/fundamental/src/sbom/endpoints/` exposes the counts at `GET /api/v2/sbom/{id}/advisory-summary`.
  - It mirrors the 404 behavior of `get.rs`.
  - Responses are cached for 5 minutes through the existing `tower-http` caching in the route builder.
- The ingestor (advisory correlation, plus SBOM re-ingestion if it writes advisory links) invalidates the cached summary for each affected SBOM after commit.
- An optional `threshold` parameter filters the counts to severities at or above the given level.
