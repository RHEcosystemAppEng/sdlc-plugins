## Architecture Summary

This feature replaces the `advisory_status` lookup table with a PostgreSQL `advisory_status_enum` enum column on the `advisory` table. The change spans five layers:

1. **Database schema** -- A reversible migration creates the enum type with values (New, Analyzing, Fixed, Rejected), adds and backfills the `status` column, drops the `status_id` FK column, and drops the `advisory_status` table
2. **Entity layer** -- SeaORM entity definitions updated to use `DeriveActiveEnum` for the status field; `advisory_status` entity removed
3. **Service layer** -- All advisory queries in `AdvisoryService` and endpoint handlers updated to use direct enum column filtering instead of `advisory_status` table joins; search service updated if affected
4. **Ingestion pipeline** -- Advisory ingestion writes `AdvisoryStatusEnum` values directly instead of inserting into the lookup table first
5. **Tests** -- Integration tests updated to use enum values in data setup and verify backward-compatible response shapes
