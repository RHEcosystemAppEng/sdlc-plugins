## Architecture Summary

The license compliance report feature adds a new read-only endpoint (`GET /api/v2/sbom/{id}/license-report`) to the trustify-backend service. The implementation follows the existing module pattern (model/ + service/ + endpoints/) and is structured in four layers:

1. **Configuration layer** (Task 1): A JSON-based license policy file (`config/license-policy.json`) defines allowed and denied licenses. A `LicensePolicy` loader in `common/src/` reads and validates the policy at startup.
2. **Model layer** (Task 1): Response structs (`LicenseGroup`, `LicenseReport`) define the API response shape with packages grouped by license and compliance flags.
3. **Service layer** (Task 2): `LicenseReportService` aggregates license data from existing `sbom_package` and `package_license` tables, walks the full transitive dependency tree, groups packages by license, and evaluates compliance against the loaded policy. No new database tables are introduced.
4. **API layer** (Task 3): An Axum handler exposes the service as `GET /api/v2/sbom/{id}/license-report`, following the existing endpoint registration pattern.

Integration tests (Task 4) verify end-to-end behavior against a real PostgreSQL test database. Documentation (Task 5) covers the endpoint API contract and policy configuration for compliance officers.
