## Architecture Summary

The feature adds a server-side advisory severity aggregation endpoint to reduce frontend round-trips for dashboard severity widgets. The implementation follows the established module pattern (model/ + service/ + endpoints/) within the existing `sbom` module:

1. **Model layer**: `AdvisorySeveritySummary` struct in `modules/fundamental/src/sbom/model/` holds the severity counts.
2. **Service layer**: `SbomService::get_advisory_summary` in `modules/fundamental/src/sbom/service/sbom.rs` performs a SeaORM aggregation query against the existing `sbom_advisory` join table, counting distinct advisories per severity level.
3. **Endpoint layer**: `GET /api/v2/sbom/{id}/advisory-summary` in `modules/fundamental/src/sbom/endpoints/` with 5-minute tower-http cache and optional `?threshold` query parameter.
4. **Cache invalidation**: The advisory ingestion pipeline in `modules/ingestor/src/graph/advisory/mod.rs` invalidates cached summaries when new advisories are linked to an SBOM.
5. **Tests**: Integration tests in `tests/api/advisory_summary.rs` following established test patterns.

No new database tables are required — the endpoint uses existing SBOM-Advisory relationship tables.
