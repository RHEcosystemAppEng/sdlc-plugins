## Architecture Summary

The plan decomposes the "Improve search experience" feature into three independent sub-features targeting the existing `modules/search/` module in trustify-backend:

1. **Performance optimization** (Task 1): Adds database indexes on searchable columns across the sbom, advisory, and package entities, and optimizes the SearchService query patterns to leverage those indexes. This is a backend-only change with no API contract modifications.

2. **Relevance ranking** (Task 2): Introduces a `SearchResultSummary` model with a relevance score field and implements PostgreSQL full-text search ranking (ts_rank) in the SearchService. The search endpoint response is extended with an additive `score` field. This follows the existing module pattern (model/ + service/ + endpoints/) already used by the fundamental modules.

3. **Filter support** (Task 3): Extends the GET /api/v2/search endpoint with optional filter query parameters (entity_type, date_range, severity) and builds filter predicate composition into the shared query builder at `common/src/db/query.rs`. All filters are optional, ensuring backward compatibility.

Workflow mode is `direct-to-main` -- each task can be merged independently without breaking existing functionality.
