## Architecture Summary

This feature replaces the `advisory_status` lookup table with a PostgreSQL `advisory_status_enum` column directly on the `advisory` table. The migration is split into two phases:

1. **Phase 1 (Task 2)**: Create the enum type, add the `status` column, and backfill from the existing lookup table join. At this point both `status_id` and `status` coexist, allowing a safe rollback window.
2. **Phase 2 (Tasks 3-5)**: Update the SeaORM entity definitions, advisory service layer, endpoints, and ingestion pipeline to use the new enum column exclusively. All `advisory_status` table references are removed from application code.
3. **Phase 3 (Task 6)**: Drop the `status_id` foreign key column and the `advisory_status` table, completing the cleanup.

The feature uses **feature-branch mode** because the migration and code changes are tightly coupled -- merging any subset to `main` independently would break either the database schema or the application queries.
