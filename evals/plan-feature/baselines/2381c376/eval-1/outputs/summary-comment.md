## Architecture Summary

The feature adds a new `GET /api/v2/sbom/{id}/advisory-summary` endpoint that returns aggregated advisory severity counts (critical, high, medium, low, total) for a given SBOM. The implementation follows the existing module pattern: a new response model (`AdvisorySeveritySummary`), a service method on `SbomService` that performs a deduplicating aggregation query against the `sbom_advisory` join table, and an endpoint handler with 5-minute `tower-http` caching. An optional `?threshold` query parameter enables severity-level filtering. Cache invalidation is added to the advisory ingestion pipeline to ensure freshness after new advisories are linked. Integration tests cover the full endpoint behavior. The feature is planned in `direct-to-main` mode — no atomicity constraints were identified.
