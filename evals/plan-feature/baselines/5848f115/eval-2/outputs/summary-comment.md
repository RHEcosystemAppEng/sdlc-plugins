### Architecture Summary

The implementation plan decomposes the "Improve search experience" feature into three independent tasks targeting the trustify-backend search module:

1. **Search filtering** adds query parameters to the existing `GET /api/v2/search` endpoint, enabling callers to narrow results by entity type (SBOM, advisory, package) and field values (severity, license, date range). Filter logic reuses the existing shared query builder in `common/src/db/query.rs`. A database migration adds B-tree indexes on filterable columns.

2. **Search relevance** introduces PostgreSQL full-text search with `tsvector`/`ts_rank` for relevance scoring. A database migration adds tsvector columns and GIN indexes to searchable entity tables. Results are sorted by relevance score by default when a search query is provided, with an optional `sort_by` parameter.

3. **Search performance** configures tower-http response caching on the search endpoint (following the existing caching middleware pattern) and optimizes SearchService query patterns to reduce database round-trips. A short cache TTL prevents serving stale data after ingestion.
