## Architecture Summary

This feature replaces the `advisory_status` lookup table with a PostgreSQL enum column (`advisory_status_enum`) directly on the `advisory` table. The migration creates the enum type, backfills existing data, drops the foreign key and lookup table. Entity definitions are updated to use SeaORM's `DeriveActiveEnum`. The advisory service, endpoints, and ingestion pipeline are simplified by removing all `advisory_status` joins. The API response shape remains unchanged — status is still serialized as a string.
