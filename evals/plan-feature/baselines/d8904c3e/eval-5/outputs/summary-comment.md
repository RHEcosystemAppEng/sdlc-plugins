## Architecture Summary

The implementation replaces the `advisory_status` lookup table with a PostgreSQL enum column (`advisory_status_enum`) directly on the `advisory` table. A reversible migration creates the enum type, adds the column, backfills existing data from the join, then drops the FK column and lookup table. SeaORM entity definitions are updated to use `DeriveActiveEnum` for the new enum type. The advisory service layer, endpoints, and ingestion pipeline are all updated to use the enum column directly, eliminating join overhead. The API response shape is unchanged — no breaking changes for API consumers.
