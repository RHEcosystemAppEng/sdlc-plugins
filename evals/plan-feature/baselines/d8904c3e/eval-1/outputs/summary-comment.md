## Architecture Summary

The feature adds a new advisory severity aggregation endpoint to the existing SBOM module in the trustify-backend service. The implementation follows the established `model/ + service/ + endpoints/` module pattern:

1. A new `AdvisorySeveritySummary` model and `SbomService` method aggregate severity counts from the existing `sbom_advisory` join table, deduplicating by advisory ID.
2. A new Axum endpoint serves the aggregated data at `GET /api/v2/sbom/{id}/advisory-summary` with a 5-minute tower-http cache.
3. The advisory ingestion pipeline is extended with cache invalidation to ensure fresh data after new advisory correlation.
4. A non-MVP optional `threshold` query parameter enables filtering counts by severity level for alerting integrations.

No new database tables are required — the feature uses existing `sbom_advisory` and `advisory` entities.
