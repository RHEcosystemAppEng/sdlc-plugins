## Workflow Mode Decision

**Selected mode:** `feature-branch`

**Rationale:** Two atomicity indicators are present:

1. **Tightly coupled feature components** -- The frontend comparison page (`/sbom/compare`) requires the new backend comparison endpoint (`GET /api/v2/sbom/compare?left={id1}&right={id2}`). Neither side functions independently: the frontend page would render empty/error states with no backend to call, and the backend endpoint has no consumer until the frontend is deployed.

2. **Breaking API changes** -- The frontend will call a backend endpoint that does not yet exist. Merging the frontend code to main without the backend endpoint would result in runtime 404 errors when users attempt to use the comparison feature.

**Interdependent tasks:**
- Task 4 (Frontend API layer) depends on Task 3 (Backend comparison endpoint) -- the frontend API client must match the backend endpoint contract
- Task 5 (Frontend comparison page) depends on Task 4 (Frontend API layer) -- the page consumes the comparison hook
- Task 6 (Frontend routing and list integration) depends on Task 5 (Frontend comparison page) -- the route points to the comparison page
