## Architecture Summary

The feature adds a new REST API endpoint `GET /api/v2/sbom/{id}/advisory-summary` that returns aggregated vulnerability advisory severity counts for a given SBOM. The implementation follows the existing module pattern (model + service + endpoints) within the SBOM module of the `modules/fundamental` crate.

Key architectural decisions:
- **No new database tables** — the aggregation query uses the existing `sbom_advisory` join table and `advisory` entity
- **Deduplication** — advisories are deduplicated by ID before counting to avoid inflated counts
- **Caching** — 5-minute cache using existing tower-http caching middleware, with invalidation in the advisory ingestion pipeline
- **Threshold filtering** (non-MVP) — optional query parameter to filter severity counts above a threshold level
