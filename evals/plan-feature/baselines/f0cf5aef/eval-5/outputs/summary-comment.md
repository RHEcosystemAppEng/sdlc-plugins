### Architecture Summary

The plan replaces the `advisory_status` lookup table with a PostgreSQL enum column (`advisory_status_enum`) on the `advisory` table. This involves a four-phase approach:

1. **Schema migration** — Create the enum type, add and backfill the column, drop the FK and lookup table (reversible)
2. **Entity layer** — Update SeaORM entity definitions to use `DeriveActiveEnum` for the new enum column
3. **Service layer** — Remove all `advisory_status` joins from advisory queries, ingestion, and search
4. **Verification** — Update integration tests and internal documentation
