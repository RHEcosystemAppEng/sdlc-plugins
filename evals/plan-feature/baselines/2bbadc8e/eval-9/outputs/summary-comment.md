## Architecture Summary

The plan decomposes the feature into three independent tasks targeting the `release-verifier` repository:

1. **Auth switch** — replaces the personal token with the service-account token and routes tracker API calls through the gateway. This is the foundational change that enables the new authentication model.

2. **Fail-closed guard** — addresses the documented fail-open risk where the tracker gateway returns a successful empty response `[]` to unauthenticated or under-privileged requests. The guard ensures that `resolve_gated_issue` in `src/gate/resolve_issue.py` exits non-zero when it cannot confirm the response came from an authenticated session, rather than silently skipping verification. The shell wrapper `scripts/pre-verify.sh` is updated to propagate this failure. This is a code-level, testable mitigation; the operational "live run after merge" mentioned in the feature's Known Risks supplements this guard but does not replace it.

3. **Status gate** — adds the business logic to check the linked issue's status and only run verification when it is "Ready for Verification".
