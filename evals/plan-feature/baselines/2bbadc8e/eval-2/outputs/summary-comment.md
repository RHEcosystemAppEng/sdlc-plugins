## Architecture Summary

The plan decomposes the "Improve search experience" feature into three independent backend tasks targeting the `modules/search/` module and shared query infrastructure in `common/src/db/`:

1. **Performance optimization** — Adds a database migration creating GIN indexes and tsvector generated columns on searchable entity tables (SBOM, advisory, package). Refactors `SearchService` to use indexed full-text search queries.
2. **Relevance ranking** — Builds on the tsvector infrastructure from Task 1 to add `ts_rank`-based result ordering, so search results are sorted by text match quality. Extends `PaginatedResults<T>` with an optional relevance score field.
3. **Search filters** — Adds optional query parameters (entity_type, severity, date_from, date_to) to the `GET /api/v2/search` endpoint, extending the shared query builder in `common/src/db/query.rs` with new filter construction helpers.

All tasks follow the existing module pattern (model/ + service/ + endpoints/), use SeaORM for database operations, and return results via the `PaginatedResults<T>` response wrapper.
