## Architecture Summary

This feature replaces the `advisory_status` lookup table with a PostgreSQL `advisory_status_enum` enum column directly on the `advisory` table. The change spans four layers:

1. **Database layer** -- a reversible migration creates the enum type, adds and backfills the column, then drops the FK column and lookup table
2. **Entity layer** -- SeaORM entity definitions are updated to use `DeriveActiveEnum` for the new enum type; the `advisory_status` entity is removed
3. **Service/API layer** -- all advisory queries drop the `advisory_status` join, and status filtering uses the enum column directly; no API response shape changes
4. **Ingestion layer** -- the ingestion pipeline writes enum values directly instead of inserting into the lookup table
