## Architecture Summary

The SBOM comparison feature follows a standard backend-to-frontend flow:

1. **Backend (Rust/Axum):** A new `SbomCompareService` computes a structured diff between two SBOMs by comparing their package lists, advisory associations, and license data on-the-fly (no new database tables). The diff result is exposed via `GET /api/v2/sbom/compare?left={id1}&right={id2}`.

2. **Frontend (React/TypeScript):** A new `SbomComparePage` at `/sbom/compare` renders the comparison results using PatternFly `ExpandableSection` components with data tables for each diff category (added/removed packages, version changes, new/resolved vulnerabilities, license changes). SBOM selection is supported both via the comparison page's `Select` dropdowns and via checkbox selection on the existing SBOM list page. URL query parameters make comparisons shareable.

3. **Cross-repo dependency flow:** Backend tasks (1-2) define the API contract first. Frontend API layer (Task 3) depends on the backend endpoint definition. Frontend UI tasks (4-6) build on the API layer. Documentation (Task 7) depends on all implementation tasks.
