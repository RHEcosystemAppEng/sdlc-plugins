### Architecture summary
A new `remediation` module in trustify-backend (`modules/fundamental/src/remediation/`, using the model/service/endpoints pattern) exposes three read-only endpoints: a severity × status summary, a paginated per-product breakdown, and a paginated vulnerability list filterable by severity, product, and status. They aggregate existing advisory/SBOM correlation data in SQL with no new tables. trustify-ui adds typed REST functions and React Query hooks for these endpoints, and a lazy-loaded `/remediation` page with PatternFly summary cards, a status-by-severity progress chart, and a server-side-filtered vulnerability table that reuses `FilterToolbar`, `SeverityBadge`, and `severityUtils`.

**Excluded:** 30-day trend chart (no historical status source without new tables) and CSV export (non-MVP, not specified). See the impact map comment for open questions.
