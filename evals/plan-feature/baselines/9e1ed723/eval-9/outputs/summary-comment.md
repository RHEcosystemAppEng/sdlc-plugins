## Architecture summary

- **Auth (Task 1):** `src/tracker/auth.py` builds the `Authorization` header from the service-account token. `src/tracker/client.py` sends all calls through the tracker API gateway. A missing token fails before any request is sent.
- **Client fail-closed (Task 2):** `src/tracker/client.py::search_issues` gets a typed `TrackerAuthError`, raised for 401/403 and for gateway 2xx-empty responses whose authentication can't be proven. The client CLI exits non-zero, and `[]` is returned only after confirmed authentication.
- **Gate + wrapper (Task 3):** `src/gate/resolve_issue.py::resolve_gated_issue` verifies only "Ready for Verification" issues. It skips with a log message on a non-ready state or an authenticated empty result, and lets `TrackerAuthError` propagate so the gate exits non-zero. `scripts/pre-verify.sh` fails on any non-zero gate exit rather than grepping for 401/403.
