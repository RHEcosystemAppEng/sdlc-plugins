## Architecture Summary

The feature adds a new `GET /api/v2/sbom/{id}/advisory-summary` endpoint to the existing SBOM module following the established model/ + service/ + endpoints/ pattern. A new `AdvisorySeveritySummary` model struct is created alongside a service method in `SbomService` that queries the `sbom_advisory` join table with `GROUP BY severity` and `COUNT(DISTINCT advisory_id)` for deduplication. The endpoint uses `tower-http` caching middleware with a 5-minute TTL, and the advisory ingestion pipeline (`modules/ingestor/src/graph/advisory/mod.rs`) is updated to invalidate cached summaries when new advisories are correlated to SBOMs. A non-MVP optional `?threshold` query parameter enables filtering severity counts for alerting integrations.

No new database tables are required — the implementation uses existing `sbom_advisory` and `advisory` tables.
