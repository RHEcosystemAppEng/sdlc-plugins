## Architecture Summary

The license compliance report is implemented as a new sub-feature within the existing SBOM module, following the established `model/ + service/ + endpoints/` structure:

1. **Domain model layer** (Task 1): A `LicensePolicy` configuration model in `common/` handles policy loading and compliance checking. `LicenseReport` and `LicenseGroup` response types in the SBOM model layer define the API response structure.

2. **Service and API layer** (Task 2): A `LicenseReportService` in the SBOM service layer aggregates package-license data from existing `sbom_package` and `package_license` entities, walks the transitive dependency tree, groups by license, and checks compliance. A new `GET /api/v2/sbom/{id}/license-report` endpoint exposes the report. Integration tests verify the full request-response cycle.

3. **Documentation** (Task 3): New content documenting the endpoint, response format, and policy configuration for compliance officers and CI/CD integration.

No new database tables are required — the report aggregates from existing package-license data. The design satisfies the p95 < 500ms performance target for SBOMs with up to 1000 packages.
