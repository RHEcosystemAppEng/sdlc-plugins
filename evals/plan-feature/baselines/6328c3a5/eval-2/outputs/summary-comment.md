## Architecture Summary

The plan improves the search experience through three independent, incrementally deliverable changes to the trustify-backend search module:

1. **Performance layer** (Task 1): A database migration adds GIN indexes for full-text search and B-tree indexes on commonly queried columns, enabling index-based query execution plans.

2. **Relevance layer** (Task 2): The SearchService is enhanced with PostgreSQL `ts_rank` scoring so results are ordered by text relevance rather than arbitrary order. This builds on the indexes from Task 1.

3. **Filtering layer** (Task 3): The search endpoint is extended with optional query parameters for entity type, date range, and severity filtering. Filters combine with AND semantics and integrate with existing pagination.

All changes follow the established module pattern (`service/ + endpoints/`), use existing shared infrastructure (`common/src/db/query.rs` for query building, `PaginatedResults<T>` for responses), and maintain backward compatibility with the existing search API contract.
