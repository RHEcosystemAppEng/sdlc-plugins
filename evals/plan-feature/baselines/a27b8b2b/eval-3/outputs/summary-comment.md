## Architecture Summary

The SBOM comparison feature adds a structured diffing capability across two repositories:

**Backend (trustify-backend):** A new `GET /api/v2/sbom/compare?left={id1}&right={id2}` endpoint computes an on-the-fly diff between two SBOMs. The comparison service queries existing package, advisory, and license data from the `sbom_package`, `sbom_advisory`, and `package_license` entity tables to produce a structured result with six diff categories: added/removed packages, version changes, new/resolved vulnerabilities, and license changes. No new database tables are introduced — the diff is computed from existing data. Performance target: p95 < 1s for SBOMs with up to 2000 packages each, achieved via HashSet/HashMap-based set operations.

**Frontend (trustify-ui):** A new SbomComparePage at `/sbom/compare` follows the Figma design with PatternFly 5 components: two Select dropdowns for SBOM selection, a Compare button, and six collapsible ExpandableSection panels with data Tables for each diff category. The page supports URL-shareable comparisons via query parameters and handles empty, loading, and error states. An Export dropdown (non-MVP) provides client-side JSON/CSV downloads. The SbomListPage is updated with multi-select checkboxes and a "Compare selected" action. Virtualized lists handle diffs with >100 changed packages.
