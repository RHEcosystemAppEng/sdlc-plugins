## Architecture Summary

This feature replaces the `advisory_status` lookup table with a PostgreSQL `advisory_status_enum` column directly on the `advisory` table. The migration is atomic and reversible, creating the enum type, adding and backfilling the column, then dropping the FK and lookup table. Entity definitions, service queries, endpoint handlers, and the ingestion pipeline are updated to use the enum column, eliminating all `advisory_status` joins. The API response shape is unchanged — status remains a string value.
