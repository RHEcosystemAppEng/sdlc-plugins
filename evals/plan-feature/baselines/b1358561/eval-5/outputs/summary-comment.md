### Architecture summary

A single atomic, reversible migration (`migration/src/m0002_advisory_status_enum`) creates `advisory_status_enum`, adds and backfills `advisory.status` (it fails closed if any row cannot be mapped), then drops `advisory.status_id` and the `advisory_status` table. A SeaORM `AdvisoryStatus` active enum in `entity/src/advisory.rs` becomes the only status mapping. AdvisoryService, the advisory list/get endpoints, and SearchService filter and read `advisory.status` with no join, and the API response still returns `status` as the same string. Unknown status filters return 400. Ingestion parses feed statuses into the enum, writes them directly, and rejects unknown values. All changes land together through the `TC-9005` feature branch, because merging only part of them would break advisory queries.

**Risk:** the zero-downtime NFR conflicts with dropping `status_id` / `advisory_status` while older binaries are still serving traffic. The migration and the binary rollout must be coordinated (see TASK-8).
