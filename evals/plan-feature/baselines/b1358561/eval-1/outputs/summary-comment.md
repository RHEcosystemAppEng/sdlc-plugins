**Architecture summary:**
A new `AdvisorySeveritySummary` model and `SbomService::advisory_severity_summary` method in
`modules/fundamental/src/sbom/` aggregate unique advisory counts per severity with a single
`COUNT(DISTINCT advisory.id) ... GROUP BY severity` query over the existing `sbom_advisory`
join table (no new tables). A new handler `sbom/endpoints/advisory_summary.rs` is registered on
the existing `/api/v2/sbom` router, returns 404 for unknown SBOMs, and caches responses per
SBOM for 5 minutes via the existing tower-http cache setup. The ingestor (advisory correlation
and SBOM re-ingestion, wired through `IngestorService`) invalidates the affected SBOM entries
after commit. An optional `?threshold` param filters counts at or above a severity. Docs, smoke
tests and performance benchmarks (from `docs/testing-readiness.md`) follow implementation.
