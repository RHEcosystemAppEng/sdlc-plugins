## Architecture Summary

This feature replaces the `advisory_status` lookup table with a PostgreSQL `advisory_status_enum` enum column on the `advisory` table. The migration creates the enum type with four values (New, Analyzing, Fixed, Rejected), adds and backfills the `status` column from the existing FK join, then drops the foreign key column and lookup table. All code layers are updated: SeaORM entity definitions switch to `DeriveActiveEnum`, the advisory service and endpoints eliminate join-based queries in favor of direct enum column filtering, and the ingestion pipeline writes enum values directly. This removes unnecessary join overhead on every advisory query (targeting approximately 40ms p95 latency reduction on the list endpoint).
