## Architecture Summary

The feature adds a new REST endpoint `GET /api/v2/sbom/{id}/advisory-summary` that returns aggregated advisory severity counts (critical, high, medium, low, total) for a given SBOM. The implementation follows the established module pattern (`model/ + service/ + endpoints/`) in the `modules/fundamental/src/sbom/` directory.

The service layer queries the existing `sbom_advisory` join table with deduplication by advisory ID and groups by severity to produce counts. An optional `?threshold` query parameter allows filtering counts to only severities at or above a given level. Responses are cached for 5 minutes using the existing tower-http caching middleware, and the advisory ingestion pipeline in `modules/ingestor/` is modified to invalidate cache entries when new advisories are linked to SBOMs.

No new database tables are required — the feature uses the existing `sbom_advisory` and `advisory` tables.
