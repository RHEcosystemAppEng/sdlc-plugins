## Architecture Summary

The license compliance report feature adds a new `GET /api/v2/sbom/{id}/license-report` endpoint to the existing SBOM module. The implementation follows the established module pattern (`model/ + service/ + endpoints/`):

1. **Data model layer** (Task 1): License policy configuration struct and compliance report response structs in `modules/fundamental/src/sbom/model/license_report.rs`. The policy is stored as a JSON config file (`license-policy.json`) and loaded by the service.

2. **Service layer** (Task 2): `LicenseReportService` in `modules/fundamental/src/sbom/service/license_report.rs` performs the core logic -- querying packages linked to an SBOM (including transitive dependencies) via the `sbom_package` and `package_license` entities, grouping by license, and checking compliance against the policy.

3. **Endpoint layer** (Task 3): Axum handler in `modules/fundamental/src/sbom/endpoints/license_report.rs` registered alongside existing SBOM routes. Returns the `ComplianceReport` as JSON.

4. **Testing** (Task 4): Integration tests in `tests/api/license_report.rs` following the existing patterns in `tests/api/sbom.rs`.

5. **Documentation** (Task 5): New content documenting the endpoint, policy configuration, and usage for compliance officers and CI/CD pipelines.

No new database tables are required -- the service aggregates data from existing `sbom_package` and `package_license` entities.
