## Architecture Summary

The feature adds a new `GET /api/v2/sbom/{id}/advisory-summary` endpoint to the trustify-backend service. The implementation follows the existing module pattern (`model/ + service/ + endpoints/`):

1. **Model layer:** A new `AdvisorySeverityCounts` struct in `modules/fundamental/src/sbom/model/` holds the severity breakdown (critical, high, medium, low, total).
2. **Service layer:** A new method on `SbomService` queries the `sbom_advisory` join table, deduplicates advisories by ID, and aggregates counts by severity level using SeaORM.
3. **Endpoint layer:** A new Axum handler at `/api/v2/sbom/{id}/advisory-summary` with 5-minute `tower-http` cache TTL and optional `?threshold=<severity>` query parameter.
4. **Cache invalidation:** The advisory ingestion pipeline in `modules/ingestor/` invalidates cached advisory-summary responses when new advisories are linked to an SBOM.
5. **Testing:** Integration tests in `tests/api/advisory_summary.rs` cover happy path, 404, deduplication, threshold filter, and cache behavior.

No new database tables are required — the implementation uses existing entity tables (`advisory`, `sbom_advisory`).
