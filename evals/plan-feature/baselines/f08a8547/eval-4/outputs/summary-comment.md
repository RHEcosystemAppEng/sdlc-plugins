The feature adds a license compliance report capability to the existing SBOM module. The implementation follows the established `model/ + service/ + endpoints/` module pattern:

1. **Model layer** (Task 1): New `LicenseReport` and `LicenseReportGroup` response types, plus a `LicensePolicy` configuration struct for defining allowed/denied licenses.
2. **Service layer** (Task 2): Report generation logic that aggregates license data from existing `package_license` and `sbom_package` entities, walks the transitive dependency tree, groups packages by license, and checks compliance against the policy.
3. **Endpoint layer** (Task 3): A new `GET /api/v2/sbom/{id}/license-report` route registered in the SBOM endpoint module.
4. **Test layer** (Task 4): Integration tests following the existing `tests/api/` patterns.
5. **Documentation** (Task 5): New content documenting the endpoint and policy configuration for compliance officers.

No new database tables are required -- the feature aggregates from existing `package_license` data. Performance target: p95 < 500ms for SBOMs with up to 1000 packages.
