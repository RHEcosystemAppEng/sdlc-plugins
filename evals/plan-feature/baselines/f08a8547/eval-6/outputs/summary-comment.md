## Architecture Summary

The backend adds a new `remediation` module following the established model/service/endpoints pattern. It provides two read-only aggregation endpoints: `GET /api/v2/remediation/summary` (severity-by-status matrix) and `GET /api/v2/remediation/by-product` (paginated per-product breakdown). All aggregations are computed from existing entity data (advisory, sbom_advisory, sbom) without new database tables, meeting the p95 < 500ms performance requirement through efficient SQL GROUP BY queries.

The frontend adds a new `RemediationDashboardPage` at `/remediation` with three visual components: summary cards (Open/In Progress/Resolved counts), a 30-day progress chart, and a filterable vulnerability table. The data layer uses the established pattern of TypeScript interfaces in `models.ts`, Axios client functions in `rest.ts`, and React Query hooks in `src/hooks/`. The table reuses existing `FilterToolbar` and `SeverityBadge` components.

A documentation task captures the "New Content" doc impact for the dashboard user guide and API endpoint reference.
