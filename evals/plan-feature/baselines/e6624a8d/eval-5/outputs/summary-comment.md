### Architecture Summary
The current advisory status design uses a `advisory_status` lookup table joined via foreign key (`status_id`) on the `advisory` table. This feature replaces that with a PostgreSQL enum type (`advisory_status_enum`) and a direct `status` column on the `advisory` table. The migration backfills existing data, drops the FK and lookup table, and all downstream code (entities, services, endpoints, ingestion) is updated to use the enum column directly. This eliminates join overhead on every advisory query and simplifies the data model.
