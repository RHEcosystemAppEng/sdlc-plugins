## Architecture Summary

The implementation adds a new advisory severity aggregation capability to the existing SBOM module following the established model/service/endpoints pattern. A new `AdvisorySeveritySummary` response model captures severity counts. The `SbomService` gains an aggregation method that queries the `sbom_advisory` join table with deduplication. A new Axum endpoint exposes this as `GET /api/v2/sbom/{id}/advisory-summary` with 5-minute tower-http caching and an optional `?threshold` query parameter. The advisory ingestion pipeline is modified to invalidate cached summaries when new advisories are linked. No new database tables are required — the implementation uses existing entity tables (`sbom_advisory`, `advisory`).
