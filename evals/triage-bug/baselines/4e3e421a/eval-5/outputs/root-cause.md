# Step 4 – Root Cause Analysis: ACME-511

**Bug**: [ACME-511](https://mock-jira.example.com/browse/ACME-511): Dark mode toggle does not persist across browser sessions

## Confidence

**Low / unconfirmed.** The available repository context (acme-backend) has no theme or
user-preference code. The root cause below is a hypothesis built from the reported behavior.
It was **not** confirmed against specific source files, and no file paths are invented here.

## 1. What is broken

The user's dark mode preference does not survive a full browser restart. After the browser
reopens, the app starts in the default light theme and the toggle shows OFF.

## 2. Why it is broken (most likely causes, in order)

1. **Preference not saved to durable storage.** The toggle updates in-memory UI state, or
   writes to `sessionStorage`. Both are cleared when the browser closes.
2. **Preference saved but not restored at startup.** The value is written (for example to
   `localStorage`, a cookie, or a user-preferences API), but the app's initialization code
   always applies the default theme, or applies it after reading the stored value.
3. **No server-side persistence.** If preferences are meant to be stored per user on the
   backend, the endpoint or field for the theme preference is missing, or the frontend never calls it.

The facts fit causes 1 or 2 best. Within one session the toggle works; it is lost only after
a *complete* browser close, which is exactly when session-scoped storage is cleared.

## 3. Where it is broken

**Not determined.** The defect is most likely in the frontend code that handles the
Settings > Appearance "Dark Mode" toggle and the app's theme initialization. That code is
not in the registered repository (`acme-backend`, a Rust backend service), and the repository
context gives no matching files. The frontend repository should be added to the Repository
Registry so the exact files and symbols can be pinned down.

## 4. How to verify the fix (reproducer strategy)

- Reproducer test (fails before the fix, passes after):
  1. Load the app with empty storage. Assert the default theme is light.
  2. Turn the Dark Mode toggle ON.
  3. Simulate a new browser session: clear in-memory state and `sessionStorage` but keep

  4. Assert the app starts in dark mode and the toggle shows ON.

- After the fix: step 4 finds dark mode with the toggle ON (matches the Expected Result).
