# Step 4.5 – Affects Version Resolution: ACME-500

## 4.5.1 – Check existing field

Step 1 recorded that the Bug's `affectsVersions` (`versions` Jira field) is **already
populated** with one value: **`0.9.0`**.

Because the field is already set, the skill must NOT silently overwrite it, and must NOT
silently skip it either. It shows the current value and waits for the user to choose:

```
Affects Version/s is already set: [0.9.0]

Options:
1. Keep — leave the current value and skip to Step 5
2. Replace — clear and set a new value
3. Augment — add additional versions alongside the current ones

Choose (1/2/3):
```

**Status: waiting for user input.** No `jira.edit_issue` call is made until the user answers.

## What happens for each choice

| Choice | Next action |
|---|---|
| **1. Keep** | Skip sub-steps 4.5.2–4.5.6. `versions` stays `[0.9.0]`. Go to Step 5 (Generate Task). |
| **2. Replace** | Run 4.5.2–4.5.5: pull a version from the Environment / Version section, find the available versions with `getJiraIssueTypeMetaWithFields(projectIdOrKey: "ACME", issueTypeId: "10020")`, match, confirm, then `jira.edit_issue("ACME-500", fields={"versions": [{"id": "<new-id>"}]})`, which replaces the existing value. |
| **3. Augment** | Same discovery, matching and confirmation as Replace, then **merge** with the existing value: `jira.edit_issue("ACME-500", fields={"versions": [{"id": "<existing-0.9.0-id>"}, {"id": "<new-id>"}]})`. |

## Notes if Replace or Augment is chosen

- **4.5.2 – Extract from description:** the Bug description has **no**
  `### **Environment / Version**` section (see bug-parsing.md). No version can be pulled from
  the description, so the flow would go to **4.5.6 (gap flagging)** unless the user picks a
  version from the available-versions list or types one in.
- **4.5.3 – Discover versions:** use Jira version IDs from the `versions.allowedValues` that
  the metadata call returns. Never hardcode IDs. (Not called in this eval: no external
  services.)
- **4.5.6 – Gap comment (only if Replace/Augment is chosen and no version can be found):**
  ```
  jira.add_comment("ACME-500", "Affects Version could not be determined from the bug
  description — please set manually.")
  ```
  followed by the standard Comment Footnote (rule + "This comment was AI-generated by
  sdlc-workflow/triage-bug v{version}.").

## Recommendation shown to the user

The existing value `0.9.0` agrees with the bug's context: the reporter filed it against the
plan-feature convention handling in the 0.9.0 plugin release. The description has no
Environment / Version section that would suggest another version. **Keep (option 1)** is the
suggested default, but the final choice is the user's.
