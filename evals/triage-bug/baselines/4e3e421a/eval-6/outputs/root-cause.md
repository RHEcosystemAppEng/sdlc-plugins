**Root Cause**

plan-feature's convention lookup does not normalize `CONVENTIONS.md` heading text. Heading
extraction uses `line[3:]`, which keeps trailing whitespace, so `## Migration Patterns  `
becomes the key `"Migration Patterns  "`. Task enrichment then does an exact match on
`"Migration Patterns"`, finds no match, and drops the convention without any warning.

**Affected Files**

- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md`: convention conformance analysis,
  heading extraction (`section_name = line[3:]`)
- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md`: convention-aware task enrichment
  (`if convention_name in discovered_conventions`)

**Suggested Approach**

- Normalize heading text at extraction by stripping leading and trailing whitespace from the
  section name. Apply the same normalization to lookup keys, so matching does not depend on
  whitespace.
- Emit a visible warning when a convention relevant to the task cannot be matched, instead
  of skipping it silently.

**Reproducer Strategy**

- Add a plan-feature eval fixture: a copy of `evals/plan-feature/files/conventions-mock.md`
  with `## Migration Patterns  ` (trailing spaces). Add an eval case asserting that the
  generated Implementation Notes include `Per CONVENTIONS.md §Migration Patterns`. It fails
  on the current skill and passes after the fix.
