# Step 4 -- Root Cause Analysis: ACME-510

## Root Cause Determination

### What is broken

The `/api/v2/advisories` endpoint does not include `X-Total-Count` and `Link`
pagination headers in the HTTP response when the request includes date range filter
parameters (`publishedAfter`, `publishedBefore`). The response body is correctly
filtered, but clients relying on pagination headers cannot determine the total number
of results or navigate to subsequent pages.

### Why it is broken

The date range filtering code path bypasses the pagination header generation logic.
When `publishedAfter` and/or `publishedBefore` query parameters are present, the
endpoint uses a filtered query path that either:

1. Constructs the database query without requesting a total count, or
2. Omits the call to the pagination header utility after obtaining query results.

The unfiltered code path correctly invokes the pagination header generation, which
confirms that the logic exists but is not wired into the filtered path. This is likely
an oversight when the date range filtering feature was added -- the filtered query
was implemented to return correct results but the developer did not connect it to the
existing pagination header mechanism.

### Where it is broken

- **API endpoint handler**: The `/api/v2/advisories` GET handler in the acme-backend
  repository -- specifically the branch that handles date range filter parameters.
- **Pagination header utility**: The existing pagination header generation function
  that sets `X-Total-Count` and `Link` headers -- this function is not called from
  the filtered query path.

### How to verify the fix

A reproducer test should:

1. Call `GET /api/v2/advisories?publishedAfter=2025-01-01&publishedBefore=2025-06-30&limit=10`
2. Assert that the response includes an `X-Total-Count` header with the correct
   integer value matching the number of advisories in the filtered date range
3. Assert that when more results exist beyond the limit, the response includes a
   `Link` header with `rel="next"` pointing to the next page
4. Verify that the response body still contains the correctly filtered advisories
