## Root Cause

The plan-feature skill's convention conformance analysis extracts CONVENTIONS.md
section headings using `line[3:]`, which captures all characters after the `## `
prefix without stripping trailing whitespace. When a heading line contains trailing
spaces (e.g., `## Migration Patterns  `), the extracted section name becomes
`"Migration Patterns  "` instead of `"Migration Patterns"`. The downstream
convention-aware task enrichment performs an exact dictionary key lookup
(`convention_name in discovered_conventions`), which fails because the stored key
includes trailing whitespace that the lookup key does not. The convention is silently
dropped with no warning or error logged.

## Affected Files

- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- convention heading
  extraction logic (`section_name = line[3:]`)
- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- convention-aware task
  enrichment logic (`if convention_name in discovered_conventions`)

## Suggested Approach

Apply `.strip()` (or `.rstrip()`) to the extracted section name at the point of
extraction: `section_name = line[3:].strip()`. This normalizes the dictionary key
regardless of trailing whitespace in the source CONVENTIONS.md file. No changes are
needed to the downstream matching logic, since it will match correctly once the key
is normalized.

## Reproducer Strategy

1. Create a test CONVENTIONS.md fixture with trailing whitespace on at least one
   heading (e.g., `## Migration Patterns  ` with two trailing spaces).
2. Run the convention heading extraction logic against this fixture.
3. Assert that the extracted section name equals `"Migration Patterns"` (without
   trailing whitespace).
4. Assert that the convention-aware task enrichment includes the expected convention
   reference in the generated Implementation Notes.
5. Also test headings with no trailing whitespace to ensure no regression.
