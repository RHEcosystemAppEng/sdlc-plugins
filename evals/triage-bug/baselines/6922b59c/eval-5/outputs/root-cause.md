# Step 4 -- Root Cause Analysis: ACME-511

## Root cause determination

### What is broken

The convention heading extraction logic in the plan-feature skill parses `CONVENTIONS.md`
headings using `line[3:]` without stripping trailing whitespace. When a heading line
contains trailing spaces (e.g., `## Migration Patterns  `), the extracted section name
includes those spaces, causing downstream exact-match lookups to fail silently.

### Why it is broken

The `line[3:]` slice extracts everything after the `## ` prefix, including any trailing
whitespace characters. Python's string slicing does not automatically strip whitespace.
The downstream comparison uses `convention_name in discovered_conventions`, which performs
an exact string match -- `"Migration Patterns"` does not equal `"Migration Patterns  "`.

### Where it is broken

- **Primary defect**: `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- the heading
  extraction logic at `line[3:]` (missing `.strip()` call)
- **Downstream impact**: `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- the
  convention-aware task enrichment fails to match conventions with trailing whitespace

### How to verify the fix

A reproducer test should:
1. Create a mock `CONVENTIONS.md` with headings containing trailing whitespace
   (e.g., `## Migration Patterns  `)
2. Run the convention extraction logic on this input
3. Assert that the extracted section name equals `"Migration Patterns"` (without
   trailing whitespace)
4. Assert that convention-aware task enrichment successfully matches the section
   by its clean name
