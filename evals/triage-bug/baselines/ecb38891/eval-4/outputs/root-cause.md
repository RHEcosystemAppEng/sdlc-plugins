# Step 4 -- Root Cause Analysis: ACME-510

## Root Cause Determination

### What is broken

The `/api/v2/advisories` endpoint omits `X-Total-Count` and `Link` pagination headers when the request includes `publishedAfter` and/or `publishedBefore` date-range query parameters. The response body returns the correct filtered results, but clients relying on pagination headers cannot determine total result count or navigate to subsequent pages.

### Why it is broken

The date-range filtered query path does not invoke the pagination header generation logic. The unfiltered advisories query path correctly computes the total count and generates pagination links, but when the handler branches into the date-filtered code path, it constructs the filtered result set without executing the count query or calling the header-setting functions. This is a missing integration -- the pagination logic was not wired into the date-filter branch.

### Where it is broken

The defect is in the advisories endpoint handler in the acme-backend repository. Specifically:

- The date-range filter query path that handles `publishedAfter`/`publishedBefore` parameters
- The pagination header generation functions (`X-Total-Count` count query and `Link` header builder) that are called from the unfiltered path but not from the filtered path

### How to verify the fix

A reproducer test should:

1. Call `GET /api/v2/advisories?publishedAfter=2025-01-01&publishedBefore=2025-06-30&limit=10` against a service with sufficient test data
2. Assert that the response includes the `X-Total-Count` header with the correct count of matching advisories
3. Assert that the response includes the `Link` header with a `rel="next"` entry when the result set exceeds the limit
4. Verify that the response body still contains the correctly filtered advisories (no regression in filtering behavior)
