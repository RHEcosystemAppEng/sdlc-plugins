# Root Cause Analysis -- Step 4

## Root Cause Determination

### What is broken

The dark mode user preference is not persisted across browser sessions. When a user toggles dark mode ON and closes the browser, the preference is lost. On reopening, the application defaults to light mode.

### Why it is broken

The preference toggle handler updates the in-memory application state (so dark mode activates immediately during the session) but does not write the preference to a persistent storage mechanism (such as `localStorage`, a cookie, or a server-side user preferences API). Alternatively, the preference may be written to `sessionStorage`, which is cleared when the browser is closed -- unlike `localStorage`, which persists across sessions.

### Where it is broken

The defect is in the settings/appearance component's toggle handler and/or the user preferences persistence layer:

- **Settings toggle handler** -- the function that handles the dark mode toggle event likely calls a state setter (e.g., `setDarkMode(true)`) without also calling a persistence function (e.g., `localStorage.setItem('darkMode', 'true')` or a user preferences API endpoint).
- **Application initialization** -- even if the preference is persisted correctly, the init code may not be reading from the persistent store to restore the preference on startup.

### How to verify the fix

A reproducer test should:
1. Simulate toggling dark mode ON
2. Verify the preference is written to the persistent store
3. Simulate a fresh application load (clearing in-memory state)
4. Verify the preference is read from the persistent store and dark mode is applied

The test should fail before the fix (preference not persisted or not restored) and pass after the fix.
