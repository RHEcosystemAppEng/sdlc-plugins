# Step 4 -- Root Cause Analysis: ACME-510

## Root Cause Determination

### What is broken

The `/api/v2/advisories` endpoint does not include `X-Total-Count` and `Link` pagination headers in the HTTP response when date-range filter query parameters (`publishedAfter`, `publishedBefore`) are used. The response body correctly returns the filtered advisories, but the pagination metadata headers are absent, preventing clients from paginating through filtered results.

### Why it is broken

The date-range filtering code path omits the total count computation required for pagination header generation. When no filters are applied, the endpoint executes a count query alongside the data query and passes the total count to the pagination header utility, which generates `X-Total-Count` and `Link` headers. When date-range filters are present, the code takes a different branch that either:

1. Skips the count query entirely, or
2. Fails to pass the count result to the pagination header generation logic

This is a conditional logic gap -- the filtered query path was implemented for data retrieval but the pagination metadata step was not wired in for that path.

### Where it is broken

- **Endpoint handler**: The `/api/v2/advisories` route handler in the acme-backend service, specifically the branch that handles requests with `publishedAfter`/`publishedBefore` query parameters.
- **Count query invocation**: The point where the total count is computed (or not) for filtered queries. The count query either needs to be added to the filtered path or the existing count query needs to incorporate the date-range filter conditions.
- **Pagination header utility call**: The invocation of the pagination header generation function from the filtered code path, which is either missing or receives incomplete parameters.

### How to verify the fix

A reproducer test should:

1. Call `GET /api/v2/advisories?publishedAfter=2025-01-01&publishedBefore=2025-06-30&limit=10` against a test dataset with known advisory records spanning the date range.
2. Assert that the response includes the `X-Total-Count` header with the correct count of advisories matching the date filter.
3. Assert that the response includes the `Link` header with `rel="next"` when total results exceed the limit.
4. Verify that the response body still contains the correct filtered advisories (no regression in data retrieval).
5. Also verify that unfiltered requests still return pagination headers (no regression).
