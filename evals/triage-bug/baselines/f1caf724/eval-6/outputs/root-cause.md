# Step 4 -- Root Cause Analysis: ACME-500

## Root Cause

The plan-feature skill's convention conformance analysis extracts CONVENTIONS.md section headings using `line[3:]` without stripping trailing whitespace. When a heading line contains trailing spaces (e.g., `## Migration Patterns  `), the extracted section name retains those spaces as `"Migration Patterns  "`. The downstream convention-aware task enrichment step performs an exact-match lookup using the clean name `"Migration Patterns"`, which fails against the whitespace-padded key. The convention is silently dropped from the generated task description with no warning or error.

## What is Broken

The heading extraction in the convention conformance analysis does not normalize whitespace. The line `section_name = line[3:]` preserves any trailing spaces from the source file, creating a mismatch between the stored key and the lookup key used during task enrichment.

## Why it is Broken

The code assumes that CONVENTIONS.md headings will never contain trailing whitespace. This is a fragile assumption -- editors frequently add trailing whitespace, and many formatters do not strip it from markdown headings. The extraction should apply `.strip()` (or equivalent) to normalize the heading text.
