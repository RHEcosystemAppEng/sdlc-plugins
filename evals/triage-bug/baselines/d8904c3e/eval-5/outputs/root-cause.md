# Step 4 -- Root Cause Analysis

## Root Cause Determination

### 1. What is broken

The dark mode preference is not persisted across browser sessions. When a user
enables dark mode via Settings > Appearance and then closes and reopens the browser,
the application reverts to light mode. The preference toggle resets to OFF.

### 2. Why it is broken

The dark mode toggle state is stored only in ephemeral memory (component state or
an in-memory store) rather than in a persistent storage medium. When the browser
is closed, all in-memory state is lost. On the next visit, the application
initializes with the default theme (light mode) because there is no persisted
preference to read.

The root cause is a **missing persistence mechanism** for the theme preference.
The toggle handler updates the UI state but does not write the preference to
localStorage, a cookie, a database, or any other persistent storage.

### 3. Where it is broken

- The Settings > Appearance component / dark mode toggle handler -- sets state
  in memory but does not persist it
- The application initialization / theme loading logic -- does not read a stored
  preference on startup (because none is stored)

### 4. How to verify the fix

A reproducer test should:
1. Simulate enabling dark mode via the toggle
2. Verify the preference is written to persistent storage (e.g., localStorage)
3. Simulate a new session (clear in-memory state, re-initialize the application)
4. Assert that the application loads in dark mode by reading the persisted preference
5. Assert the toggle shows ON state
