# Step 4 -- Root Cause Analysis: ACME-510

## Root Cause Determination

### What is broken

The `GET /api/v2/advisories` endpoint fails to return `X-Total-Count` and `Link` pagination headers when date-range filter parameters (`publishedAfter`, `publishedBefore`) are present in the request. The response body correctly contains the filtered advisories, but clients cannot determine the total result count or navigate pages.

### Why it is broken

The date-range filtering code path in the advisory listing handler either:
1. Takes a separate execution branch that bypasses the pagination header generation logic, or
2. Fails to pass the date-range filter criteria to the count query used to compute the total, causing the count to be unavailable or zero, which results in the headers being omitted.

The unfiltered path works correctly because it follows the standard pagination flow that includes both the count query and header generation. The date-range filtered path was likely added later and did not integrate with the existing pagination infrastructure.

### Where it is broken

- **Primary:** The advisory endpoint handler (likely in `src/api/v2/advisories.rs` or equivalent route handler file) where date-range query parameters are processed and the filtered query is constructed.
- **Secondary:** The pagination utility or middleware that generates `X-Total-Count` and `Link` headers, if it has conditional logic that excludes certain query paths.

### How to verify the fix (Reproducer Strategy)

A reproducer test should:

1. **Setup:** Seed the test database with a known set of advisories spanning multiple dates (e.g., 15+ advisories published across a date range).
2. **Execute:** Call `GET /api/v2/advisories?publishedAfter=<start>&publishedBefore=<end>&limit=10` where the date range includes more than 10 matching advisories.
3. **Assert (before fix -- expected failure):**
   - Verify `X-Total-Count` header IS present and equals the total count of matching advisories.
   - Verify `Link` header IS present with `rel="next"` when more pages exist.
4. **Assert (after fix -- expected pass):**
   - Same assertions pass: both pagination headers are present with correct values.
5. **Regression check:** Also verify that the unfiltered endpoint (`GET /api/v2/advisories?limit=10`) still returns pagination headers correctly.
