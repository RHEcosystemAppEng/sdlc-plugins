## Affected Files and Symbols

### File: plugins/sdlc-workflow/skills/plan-feature/SKILL.md

#### Convention heading extraction (defect location)

```python
for line in conventions_content.split('\n'):
    if line.startswith('## '):
        section_name = line[3:]  # Extracts heading text after "## "
        conventions[section_name] = current_section_content
```

**Finding**: The heading extraction at `line[3:]` does NOT call `.strip()` or `.rstrip()` on the extracted text. When the heading line is `## Migration Patterns  \n`, the extracted section name becomes `"Migration Patterns  "` (with trailing spaces).

#### Convention-aware task enrichment (failure point)

```python
if convention_name in discovered_conventions:
    notes.append(f"Per CONVENTIONS.md {convention_name}: {action}")
```

**Finding**: This lookup uses exact string matching via `in` (dictionary key lookup). The key `"Migration Patterns  "` (with trailing spaces) does not match the expected key `"Migration Patterns"` (without trailing spaces), so the convention is silently skipped. No warning or fallback logic exists.

## Persistence-Impact Analysis

The buggy function's output is the **task description text** generated by the plan-feature skill. This output is written to a Jira issue description (via the Jira API), not to a local database.

**Trace**: `line[3:]` (heading extraction) -> `conventions[section_name]` (dictionary storage) -> `convention_name in discovered_conventions` (lookup failure) -> `notes.append(...)` (skipped) -> Jira task description (missing convention reference).

**Conclusion**: The output is persisted to Jira as part of task creation, but this is a **text content correctness** issue, not a data value corruption issue. Previously created tasks that were affected by this bug would have missing convention references in their Implementation Notes. However, since tasks are human-reviewed and Jira content is mutable, no automated data migration is needed. The fix corrects future task generation.

**Persistence boundary**: Not applicable -- no database migration required.
