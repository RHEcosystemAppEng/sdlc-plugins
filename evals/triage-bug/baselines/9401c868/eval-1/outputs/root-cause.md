## Root Cause

The plan-feature skill's convention conformance analysis extracts CONVENTIONS.md section
headings using `line[3:]`, which preserves any trailing whitespace present on the heading
line. When a heading such as `## Migration Patterns  ` (with trailing spaces) is parsed,
the extracted key becomes `"Migration Patterns  "` instead of `"Migration Patterns"`. The
subsequent convention-aware task enrichment performs an exact-match lookup against the clean
convention name, which fails silently -- no warning or error is emitted, and the convention
is omitted from the generated task description.

## Affected Files

- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- convention lookup logic
  (heading extraction at `section_name = line[3:]`)
- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- convention-aware task enrichment
  (exact-match comparison `if convention_name in discovered_conventions`)

## Suggested Approach

1. Add `.strip()` (or `.rstrip()`) to the heading extraction to normalize trailing
   whitespace: `section_name = line[3:].strip()`.
2. Consider adding a warning log when a convention heading is parsed but does not match
   any expected convention name, to prevent silent failures in the future.

## Reproducer Strategy

1. Create a CONVENTIONS.md fixture with trailing whitespace on at least one heading
   (e.g., `## Migration Patterns  ` with two trailing spaces).
2. Run the plan-feature convention conformance analysis against this fixture with a
   feature that should trigger the convention.
3. Assert that the generated task's Implementation Notes include the convention reference
   (e.g., `Per CONVENTIONS.md Migration Patterns: ...`).
4. Before the fix, this test should fail (convention is silently dropped). After the fix,
   it should pass (convention is included despite trailing whitespace on the heading).
