# Step 4 -- Root Cause Analysis

## Root Cause Determination

### What is broken

The `GET /api/v2/advisories` endpoint does not include pagination headers (`X-Total-Count` and `Link`) in the HTTP response when the request includes date range filter parameters (`publishedAfter`, `publishedBefore`). The response body correctly contains filtered advisory data, but clients cannot determine total result count or navigate to subsequent pages.

### Why it is broken

The date-filtered query path in the advisories endpoint handler does not execute the count query or does not pass its result to the pagination header construction logic. The unfiltered code path correctly performs both the data query and the count query, then sets the pagination headers. When date filters are introduced, the handler likely takes a different branch that either:

- Skips the total count query that feeds `X-Total-Count`
- Bypasses the pagination header helper function that builds the `Link` header
- Returns the response before the header-setting code runs

The data query itself applies the date filters correctly (the body is correct), confirming that the filter parsing works. The defect is specifically in the omission of the count/header logic on the filtered path.

### Where it is broken

- **Primary**: The advisories endpoint handler (likely `src/api/v2/advisories.rs` or equivalent) -- the function handling `GET /api/v2/advisories` where the date filter branch diverges from the standard pagination flow.
- **Secondary**: The query builder for advisories with date range filters -- if it uses a separate function that does not return a total count alongside the results.

### How to verify the fix

A reproducer test should:

1. Call `GET /api/v2/advisories?publishedAfter=2025-01-01&publishedBefore=2025-06-30&limit=10` against test data known to contain more than 10 matching advisories.
2. Assert that the response includes the `X-Total-Count` header with a value matching the total number of matching advisories.
3. Assert that the response includes the `Link` header with a `rel="next"` entry (since total > limit).
4. Verify that the response body still contains the correct filtered advisories (no regression).
