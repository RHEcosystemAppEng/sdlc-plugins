## Root Cause Analysis

**Root Cause**

plan-feature's convention conformance analysis takes `CONVENTIONS.md` section names from heading
lines with `section_name = line[3:]`. It does not strip trailing whitespace. A heading such as
`## Migration Patterns  ` is stored under the key `"Migration Patterns  "`. The convention-aware
task enrichment step later checks `if convention_name in discovered_conventions` with the
normalized name `"Migration Patterns"`. That exact-match check fails. The miss has no fallback and
logs no warning, so the convention is left out of the generated task's Implementation Notes
without notice.

- **What is broken:** CONVENTIONS.md section-name extraction and lookup
- **Why:** extracted heading text is not normalized (trailing spaces, tabs, or `\r` are kept), and the lookup is an exact string match with no diagnostic on a miss
- **Where:** `plugins/sdlc-workflow/skills/plan-feature/SKILL.md`

**Affected Files**

- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md`, Convention conformance analysis (heading extraction `section_name = line[3:]`). This is where the defect originates.
- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md`, Convention-aware task enrichment (`if convention_name in discovered_conventions`). This is where the defect shows up as a silent miss.
- `evals/plan-feature/files/conventions-mock.md` is the existing fixture. It has no trailing-whitespace headings, so the gap is not covered.

**Suggested Approach**

1. Normalize heading text when it is extracted: strip leading and trailing whitespace, including `\r`, from the section name.
2. Apply the same normalization to the lookup key in the task enrichment step so both sides match.
3. Log a warning when a convention section is expected but not matched, so a mismatch can no longer pass silently.

No data migration is needed. The output is computed per run and is not persisted.

**Reproducer Strategy**

Add a plan-feature eval fixture whose `CONVENTIONS.md` has the heading `## Migration Patterns  `
(with trailing spaces) followed by `Add Index::create() for all FK columns.` Run plan-feature on a
feature that needs an FK migration. Assert that the generated task's Implementation Notes contain
`Per CONVENTIONS.md §Migration Patterns: add Index::create() for all FK columns.` The assertion
fails before the fix (the note is absent) and passes after it.
