The repository context provided for this triage (`repo-context-mock.md`) covers a different bug (ACME-500, CONVENTIONS.md heading whitespace in plan-feature). The defect location must be confirmed before or at the start of implementation.

## 1. What is broken
`GET /api/v2/advisories` leaves out the `X-Total-Count` and `Link` (rel="next") response headers when the request includes the date-range filter (`publishedAfter` / `publishedBefore`, called `filterDateRange` in the description). The body is correct. Unfiltered requests return the headers correctly.

## 2. Why it is broken (hypothesis)
The headers are present on the unfiltered path and absent on the filtered path, while the body is correct on both. That pattern suggests the date-range filter is served by a **separate code branch** (a separate query or service function, or a separate response construction) that returns the filtered items but either:
- (a) does not compute the total count, so header emission is skipped (for example, the count is `None` or `Option` and headers are only set when it is `Some`), or
- (b) builds the response directly instead of going through the shared pagination wrapper or helper that adds `X-Total-Count` / `Link`.

A secondary possibility to check: the `Link` URL builder may fail, or be skipped, when serializing the extra query parameters (`publishedAfter` / `publishedBefore`). That would explain a missing `Link` header but not a missing `X-Total-Count`, so (a) or (b) is more likely. The reporter says both headers are missing.

## 3. Where it is broken
**Not determined.** The candidate locations, which are unverified and need the searches listed in investigation.md:
- the advisories handler for `GET /api/v2/advisories` in acme-backend, specifically its date-filter branch
- the advisory service or query function used when date filters are present
- the shared pagination-header helper or middleware and its callers

No concrete file paths or symbols are given, because none were found in the provided context.

## 4. How to verify the fix (reproducer strategy)
An endpoint-level integration test in acme-backend should:
1. Seed more advisories than `limit` whose `published` dates fall inside 2025-01-01..2025-06-30, plus some outside that range.
2. Call `GET /api/v2/advisories?publishedAfter=2025-01-01&publishedBefore=2025-06-30&limit=10`.
3. Assert that the `X-Total-Count` header is present and equals the number of seeded advisories inside the range, not the overall total.
4. Assert that the `Link` header is present, contains `rel="next"`, and that the next URL **keeps** the `publishedAfter` / `publishedBefore` parameters.
5. Control case: the same assertions without the date filter still pass.

Before the fix, steps 3 and 4 fail (headers absent). After the fix, they pass.
