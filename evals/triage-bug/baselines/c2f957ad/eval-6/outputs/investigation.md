# Steps 2–3 — Reproduce/Trace and Codebase Investigation (ACME-500)

## Step 2 — Reproduce/Trace

### Runnable reproduction
The Steps to Reproduce require a `/plan-feature` skill run against a live Jira feature (ACME-100). That cannot be run as a read-only command, so direct reproduction was **not attempted**. Code-path tracing was used instead.

### Code-path trace
1. **Entry point**: `/plan-feature ACME-100`. plan-feature reads the target repo's `CONVENTIONS.md` during convention conformance analysis.
2. **Heading extraction** (`plugins/sdlc-workflow/skills/plan-feature/SKILL.md`, convention conformance analysis):
   ```python
   for line in conventions_content.split('\n'):
       if line.startswith('## '):
           section_name = line[3:]
           conventions[section_name] = current_section_content
   ```
   With the input line `## Migration Patterns  `, `section_name` becomes `"Migration Patterns  "`, keeping the two trailing spaces.
3. **Enrichment lookup** (`plugins/sdlc-workflow/skills/plan-feature/SKILL.md`, convention-aware task enrichment):
   ```python
   if convention_name in discovered_conventions:
       notes.append(f"Per CONVENTIONS.md §{convention_name}: {action}")
   ```
   The lookup key `"Migration Patterns"` does not exactly match the stored key `"Migration Patterns  "`. The `if` is false, no note is added, and there is **no else branch or warning**.
4. **Divergence point**: the behavior first goes wrong at the `line[3:]` extraction, which does not normalize whitespace. The silent drop then happens at the enrichment membership check, which has no fallback or diagnostic.

Trace outcome: **confirmed by code-path analysis**. The trace accounts for both the missing convention (Actual Result) and the lack of any warning.

## Step 3 — Codebase Investigation

### Target repository
- Component `sdlc-workflow` and the code path `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` identify the repository as **`acme-backend`** in the Registry (Serena instance `serena_backend`, path `/home/dev/repos/acme-backend`). It is the only registered repository.
- Code Intelligence says no Serena servers are configured, so the skill uses the **Read/Grep/Glob fallback**. In this eval, the repository content was taken from `repo-context-mock.md`.

### Affected files and symbols

| File | Location / symbol | Role in bug |
|---|---|---|
| `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` | Convention conformance analysis: heading-parsing loop (`section_name = line[3:]`) | **Defect origin**: stores heading keys with trailing whitespace |
| `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` | Convention-aware task enrichment: `if convention_name in discovered_conventions` | **Manifestation**: exact-match lookup fails and the convention is dropped with no warning |

### Impact analysis
- Any `CONVENTIONS.md` heading with trailing spaces or tabs, or with a trailing `\r` from CRLF line endings when the content is split on `\n` only, is stored under a key that does not match. The convention is dropped silently.
- Every convention section is affected, not just Migration Patterns. Tasks generated by plan-feature for repos with such files are missing convention guidance.
- Only consumers of plan-feature output are affected downstream, through generated task Implementation Notes. No other skills share this parsing logic according to the provided context.

### Test files and patterns
- `evals/plan-feature/files/conventions-mock.md` is the existing plan-feature conventions eval fixture. It has **no trailing whitespace on headings**, so current evals do not cover this edge case.
- The reproducer should follow this repo's eval pattern: a fixture file under `evals/plan-feature/files/` plus an eval entry with assertions in `evals/plan-feature/evals.json`.

### Reuse candidates
- Python `str.strip()` / `str.rstrip()` normalizes the extracted heading. No new helper is needed.
- The existing fixture `evals/plan-feature/files/conventions-mock.md` can be used as the template for the new trailing-whitespace fixture.

### CONVENTIONS.md lookup
- The repository has **no `CONVENTIONS.md`** at its root, so no repo-specific conventions apply to the fix task.

### Persistence-impact analysis
- The buggy output is the parsed convention section names. They are used in memory to build Implementation Notes text for a generated Jira task.
- Tracing from `section_name` → `conventions` dict → `discovered_conventions` → `notes.append(...)` → task description text. **No database write is involved.** The only persisted artifact is the Jira task description, which is not a database record maintained by this codebase.
- **No persistence boundary found. No data migration is needed.** Previously generated tasks that are missing conventions could be regenerated or edited by hand if needed. That is outside the code fix.

### Decomposition Guard (Step 6) check
There is a single root cause: heading text is not normalized at extraction. It shows up at a second point, the silent exact-match lookup. Adding a warning for unmatched conventions is part of the same fix and does not address a separate root cause. **This does not trigger decomposition.** One Task is appropriate.
