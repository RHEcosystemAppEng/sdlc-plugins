## What is broken

The user's dark-mode preference does not survive a full browser restart: after toggling
Dark Mode ON and reopening the browser, the app loads in light mode and the toggle shows OFF.

## Why it is broken (hypotheses, in order of likelihood)

1. **Preference held only in volatile state** — the toggle updates in-memory app state
   (or `sessionStorage`, which is cleared when the browser closes) but never writes to
   durable storage (`localStorage`, a persistent cookie, or a server-side user-settings
   record).
2. **Preference written but not read on startup** — the value is persisted, but theme
   initialization runs with a hard-coded light default and never hydrates from storage
   (or the toggle component initializes from the default rather than the stored value).
3. **Server-side save not wired** — if preferences are stored in acme-backend, the
   settings PUT/save call may not be made, may fail silently, or the GET used on load may
   not return the theme field.

The fact that the toggle itself resets to OFF (not just the theme) suggests that no stored
value is available to the UI on load — consistent with hypotheses 1 or 3.

## Where it is broken

**Undetermined.** No files or symbols were identified. The registered repository
(acme-backend, Rust) is likely not where client-side theme logic lives; the frontend
repository may need to be added to the Repository Registry.
