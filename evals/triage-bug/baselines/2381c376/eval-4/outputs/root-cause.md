# Step 4 -- Root Cause Analysis: ACME-510

## Root Cause Determination

### What is broken

The `GET /api/v2/advisories` endpoint does not return `X-Total-Count` and `Link`
pagination headers when date-range filter parameters (`publishedAfter`,
`publishedBefore`) are included in the request. The response body correctly contains
the filtered advisory results, but clients relying on pagination headers cannot
determine the total number of matching records or navigate to subsequent pages.

### Why it is broken

The endpoint handler has two distinct query paths: one for unfiltered listing and one
for date-filtered listing. The unfiltered path includes a call to
`add_pagination_headers()` (or equivalent), which performs a separate count query and
sets the `X-Total-Count` and `Link` headers on the response. The filtered path was
implemented without wiring in this pagination header logic -- it constructs the
filtered query correctly and returns the right result set, but bypasses the count
query and header-setting step entirely.

This is a code-path omission: the date-range filtering feature was added without
integrating the existing pagination header utility that other query paths use.

### Where it is broken

- **Primary defect**: the filtered query branch in the advisories endpoint handler
  (e.g., `src/api/v2/advisories.rs` or `src/handlers/advisories.rs`, in the
  `list_advisories` function or equivalent) -- missing call to `add_pagination_headers()`
  after the filtered query executes.
- **Related utility**: `add_pagination_headers()` -- the existing function that computes
  and sets pagination headers, already used by the unfiltered path and other endpoints.

### How to verify the fix

A reproducer test should:

1. Call `GET /api/v2/advisories?publishedAfter=2025-01-01&publishedBefore=2025-06-30&limit=10`
   against a test instance with sufficient advisory data.
2. Assert that the response includes the `X-Total-Count` header with the correct count
   of matching advisories.
3. Assert that the response includes the `Link` header with a `rel="next"` entry when
   more pages exist.
4. The test should fail before the fix (headers absent) and pass after the fix (headers
   present with correct values).
