## Root Cause

The plan-feature skill's convention conformance analysis extracts `CONVENTIONS.md` section headings using `line[3:]`, which captures everything after the `## ` prefix but does not strip trailing whitespace. When a heading line contains trailing spaces (e.g., `## Migration Patterns  `), the extracted key becomes `"Migration Patterns  "` instead of `"Migration Patterns"`. The downstream convention-matching step performs an exact string comparison (`if convention_name in discovered_conventions`), which fails because the lookup key lacks the trailing whitespace. No warning or fallback is triggered, so the convention is silently dropped from the generated task description.

## Affected Files

- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- Convention conformance analysis section:
  - **Heading extraction**: `section_name = line[3:]` -- missing `.strip()` call
  - **Convention matching**: `if convention_name in discovered_conventions` -- exact match assumes clean keys

## Suggested Approach

Add a `.strip()` call to the heading extraction to normalize the section name:

```
section_name = line[3:].strip()
```

This ensures trailing whitespace in `CONVENTIONS.md` headings is removed before the section name is stored as a dictionary key, so downstream exact-match lookups succeed regardless of trailing whitespace in the source file.
