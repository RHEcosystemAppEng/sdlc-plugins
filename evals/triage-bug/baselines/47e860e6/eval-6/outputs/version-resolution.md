# Step 4.5 — Affects Version Resolution (ACME-500)

## 4.5.1 — Check existing field

Step 1 recorded that the Bug's `affectsVersions` (Jira `versions` field) is **already populated**:

- Affects Version/s: **0.9.0**

Because the field already has a value, the skill does **not** extract and set a version automatically, and it does **not** overwrite the existing value. It shows the current value and asks the user what to do:

```
Affects Version/s is already set: [0.9.0]

Options:
1. Keep — leave the current value and skip to Step 5
2. Replace — clear and set a new value
3. Augment — add additional versions alongside the current ones

Choose (1/2/3):
```

**Awaiting user input.** No answer has been invented. `jira.edit_issue` is **not** called before the user replies.

## Behaviour per user choice

### Option 1 — Keep (expected/default path)
- Skip sub-steps 4.5.2–4.5.6 entirely.
- No `jira.edit_issue` call and no gap-flag comment.
- The Affects Version/s field stays `0.9.0`. Go to Step 5.

### Option 2 — Replace
- 4.5.2: extract version identifiers from the **Environment / Version** section. That section is **missing** from the ACME-500 description (see bug-parsing.md), so no version can be extracted from the description.
- So the skill goes to **4.5.6 gap handling**. Because the user chose Replace on purpose, the skill would first ask the user to pick a replacement from the available Jira versions (4.5.3 discovery via `jira.getJiraIssueTypeMetaWithFields(projectIdOrKey: "ACME", issueTypeId: "10020")`, reading `versions.allowedValues`) or type one manually. If none can be decided, it posts the gap comment:
  > "Affects Version could not be determined from the bug description — please set manually."
  >
  > ---
  > This comment was AI-generated by sdlc-workflow/triage-bug v0.13.10.
- Any update uses the Jira version **ID** returned by discovery: `jira.edit_issue("ACME-500", fields={"versions": [{"id": "<discovered-id>"}]})`. IDs are never hardcoded.

### Option 3 — Augment
- Same extraction and discovery as Replace. There is no description-derived version, so the user picks additional version(s) from the discovered list.
- **Merge** with the existing value instead of replacing it: `jira.edit_issue("ACME-500", fields={"versions": [{"id": "<id-of-0.9.0>"}, {"id": "<new-id>"}]})`. The existing `0.9.0` entry is kept.
