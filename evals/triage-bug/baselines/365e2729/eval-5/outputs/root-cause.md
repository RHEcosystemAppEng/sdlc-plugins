## What is broken

The user's dark-mode preference does not survive a full browser restart. After
reopening, the app renders in light mode and the toggle shows OFF.

## Why it is broken (hypothesis, ordered by likelihood)

1. **Preference kept only in memory or session-scoped storage.** The toggle updates
   in-memory UI state, `sessionStorage`, or a session cookie (no `Expires`/`Max-Age`).
   All of these are cleared when the browser closes.
2. **Preference written but not read back on startup.** The value is saved to
   `localStorage` or a persistent cookie, but app initialisation always uses the
   default theme (light) instead of reading the stored value. Initialisation may
   also overwrite the stored value with the default.
3. **Server-side preference not saved or not loaded.** If preferences are meant to
   be saved per user in acme-backend, the settings update isn't sent to or stored by
   the backend, or the user-settings response omits the theme field when the app
   starts.

Since the toggle state itself resets to OFF, the source of truth read at startup is
returning the default. That fits causes 1 and 2 (no value stored, or value ignored)
better than a rendering problem.
