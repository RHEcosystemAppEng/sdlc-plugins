# Step 4 -- Root Cause Analysis: ACME-500

## Root Cause Determination

### What is broken

The plan-feature skill's convention conformance analysis silently drops conventions from `CONVENTIONS.md` when heading lines contain trailing whitespace. The heading extraction logic (`line[3:]`) preserves trailing whitespace in the dictionary key, but the downstream exact-match lookup uses a clean (no trailing whitespace) convention name. The mismatch causes the convention to be silently skipped with no warning or error.

### Why it is broken

The heading extraction code uses a raw slice (`line[3:]`) to extract the heading text after the `## ` prefix, without stripping trailing whitespace. This is a missing input normalization step. The downstream consumer performs an exact string comparison (`if convention_name in discovered_conventions`) which naturally fails when the key has trailing spaces but the lookup value does not.

Additionally, the failure is silent -- there is no warning logged when a convention name fails to match, making the bug difficult to detect in practice.

### Where it is broken

**Primary defect:**
- **File:** `plugins/sdlc-workflow/skills/plan-feature/SKILL.md`
- **Symbol:** Convention heading extraction loop
- **Line:** `section_name = line[3:]` -- missing `.strip()` call

**Secondary failure point (silent drop):**
- **File:** `plugins/sdlc-workflow/skills/plan-feature/SKILL.md`
- **Symbol:** Convention-aware task enrichment
- **Line:** `if convention_name in discovered_conventions` -- exact match with no fallback or warning
