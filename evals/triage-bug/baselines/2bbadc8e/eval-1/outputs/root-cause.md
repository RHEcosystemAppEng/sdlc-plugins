## Root Cause

The plan-feature skill's convention heading extraction uses `line[3:]` to extract the
section name after the `## ` prefix. This slicing preserves any trailing whitespace
present on the heading line. When `CONVENTIONS.md` contains a heading like
`## Migration Patterns  ` (with trailing spaces), the extracted section name becomes
`"Migration Patterns  "` instead of `"Migration Patterns"`.

The downstream convention-aware task enrichment performs an exact string match
(`convention_name in discovered_conventions`) against the extracted section names.
Because the stored key includes trailing whitespace, the lookup silently fails -- the
convention is skipped with no warning or error logged.

## Affected Files

- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- convention heading extraction
  logic (`line[3:]` without `.strip()`)
- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- convention-aware task enrichment
  (exact-match lookup against unstripped keys)

## Suggested Approach

1. Change the heading extraction from `line[3:]` to `line[3:].strip()` to normalize
   section names by removing leading and trailing whitespace.
2. Optionally, add defensive `.strip()` on the lookup side as well, so both the stored
   key and the query key are normalized.
3. No data migration is needed -- convention references are computed at task-generation
   time, not persisted to a database.

## Reproducer Strategy

1. Create a `CONVENTIONS.md` eval fixture with trailing whitespace on at least one
   heading (e.g., `## Migration Patterns  ` with two trailing spaces).
2. Run the convention extraction logic against this fixture.
3. Assert that the extracted section name is `"Migration Patterns"` (trimmed), not
   `"Migration Patterns  "` (with trailing spaces).
4. Assert that the convention-aware task enrichment includes the expected convention
   reference in the generated task output.
