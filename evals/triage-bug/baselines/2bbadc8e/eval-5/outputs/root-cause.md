# Step 4 -- Root Cause Analysis

## Root Cause Determination

### What is broken

The settings/preference key extraction logic does not strip trailing whitespace from parsed section headings. When the dark mode preference is toggled, the application attempts to persist the preference using the extracted key. The key contains trailing whitespace (e.g., `"Dark Mode  "` instead of `"Dark Mode"`), causing the exact-match lookup against known preference identifiers to fail silently. As a result, the preference is never persisted, and the application reverts to the default (light mode) on the next session.

### Why it is broken

The heading extraction code uses `line[3:]` to extract the section name after the `## ` prefix, but does not call `.strip()` on the result. Markdown headings may contain trailing spaces (e.g., from editor padding or copy-paste), and these are carried through into the extracted key. The downstream match (`if convention_name in discovered_conventions`) performs an exact string comparison, so `"Dark Mode  "` != `"Dark Mode"` and the match fails.

### Where it is broken

- **File**: `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- heading extraction at `line[3:]`
- **File**: `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- convention-aware task enrichment exact-match comparison

### How to verify the fix

A reproducer test should:
1. Create a mock settings/conventions content with trailing whitespace on a heading (e.g., `## Dark Mode  \n`)
2. Run the extraction logic
3. Assert that the extracted key matches `"Dark Mode"` (without trailing whitespace)
4. Assert that the preference persistence succeeds when the key matches correctly
