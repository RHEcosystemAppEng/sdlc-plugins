# Step 4 -- Root Cause Analysis: ACME-510

## Root Cause Determination

### What is broken

The `GET /api/v2/advisories` endpoint does not include `X-Total-Count` and `Link`
pagination headers in the HTTP response when the request contains date range filter
parameters (`publishedAfter` and `publishedBefore`). The response body contains the
correct filtered advisory results, but the pagination metadata headers are absent.

### Why it is broken

The date-range-filtered query path omits the pagination header generation step. The
unfiltered code path correctly computes the total count of matching records and sets
the `X-Total-Count` and `Link` headers before returning the response. When the
date range filter parameters are present, execution follows a different branch that
either:

1. Uses a separate query function that does not invoke the pagination header helper, or
2. Bypasses the total-count query that feeds the header values, or
3. Constructs the response without calling the header-setting logic.

The root cause is that the filtered query path was implemented without integrating the
existing pagination header logic that the unfiltered path already uses.

### Where it is broken

- **Advisories endpoint handler** -- the route handler for `GET /api/v2/advisories`
  in the acme-backend service. The specific file and function would be identified
  by searching for the route definition (e.g., `/api/v2/advisories`) and tracing the
  handler through the date-range-filtered branch.
- **Pagination header helper** -- the utility that sets `X-Total-Count` and `Link`
  headers. This code works correctly for unfiltered requests but is not invoked from
  the filtered path.

### How to verify the fix

A reproducer test should:

1. Call `GET /api/v2/advisories?publishedAfter=2025-01-01&publishedBefore=2025-06-30&limit=10`
   against a test dataset with known advisory records in that date range.
2. Assert that the response includes the `X-Total-Count` header with the correct
   total count of matching advisories.
3. Assert that the response includes the `Link` header with a `rel="next"` link
   when additional pages exist.
4. Verify that the response body still contains the correct filtered results
   (no regression in the filtering logic).
5. Verify that non-filtered requests continue to return pagination headers correctly
   (no regression in the unfiltered path).
