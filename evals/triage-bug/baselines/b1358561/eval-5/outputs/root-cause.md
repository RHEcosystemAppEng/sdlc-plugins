## What is broken
The dark-mode preference set in Settings > Appearance is not restored after a full
browser restart; the app falls back to the default (light) theme and the toggle
shows OFF.

## Why it is broken (candidate causes, in order of likelihood)
1. **Non-durable storage** — the toggle writes to in-memory app state or
   `sessionStorage`, both of which are cleared when the browser closes, instead of
   `localStorage`/a persistent cookie or the backend user-preferences store.
2. **Write succeeds but startup ignores it** — the preference is persisted, but
   theme initialization on app load hard-codes the default theme (or runs before
   the stored value / user-preferences API response is read) and overwrites it.
3. **Backend preference not saved** — the UI calls an acme-backend preferences
   endpoint, but the theme field is dropped or not persisted server-side, so the
   next session reads back the default.

The symptom "toggle is reset to OFF" (not just the theme) indicates the UI state is
initialized from the default rather than from any stored value, which is consistent
with all three candidates; distinguishing them requires the code.

## Where it is broken
Undetermined. Likely locations: the Settings > Appearance toggle handler, the
theme provider / app bootstrap, and (if candidate 3) the acme-backend
user-preferences handler. Exact paths must be discovered in the front-end
repository, which is not in the Repository Registry.

## How to verify the fix (reproducer strategy)
- Test: set dark mode ON via the toggle, then simulate a new browser session
  (clear in-memory state and `sessionStorage` but keep durable storage — or
  re-fetch preferences from the backend), re-initialize the app, and assert the
  active theme is `dark` and the toggle reads ON.
- Before fix: asserts fail (theme `light`, toggle OFF) — matching Actual Result.
- After fix: asserts pass — matching Expected Result.
- If candidate 3 applies, add a backend test: save preference `theme=dark` for a
  user, read it back in a fresh request, assert `dark`.
