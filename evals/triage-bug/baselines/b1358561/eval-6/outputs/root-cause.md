# Step 4 – Root Cause Analysis: ACME-500

## What is broken

plan-feature's convention conformance analysis does not recognise a CONVENTIONS.md section when its `## ` heading line has trailing whitespace. That convention is then left out of the generated task's Implementation Notes.

## Why it is broken

1. **Missing normalisation:** heading extraction uses `section_name = line[3:]` without stripping whitespace. `## Migration Patterns  ` is stored under the key `"Migration Patterns  "`.
2. **Exact-match lookup:** task enrichment checks `convention_name in discovered_conventions` with the clean name `"Migration Patterns"`. That check fails against the key with trailing spaces.
3. **Silent failure:** no fallback and no warning when an expected convention is not found, so the user gets no signal that the convention was dropped.

## Where it is broken

- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` — Convention conformance analysis (heading extraction: `section_name = line[3:]`)
- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` — Convention-aware task enrichment (`if convention_name in discovered_conventions:`)

## How to verify the fix (reproducer strategy)

- Fixture: a CONVENTIONS.md variant where `## Migration Patterns  ` (two trailing spaces) is followed by `Add Index::create() for all FK columns.`
- Scenario: run plan-feature on a feature that needs a DB migration with foreign keys (as for ACME-100).
- Before the fix: generated Implementation Notes do NOT contain `Per CONVENTIONS.md §Migration Patterns` (the bug).
- After the fix: generated Implementation Notes contain `Per CONVENTIONS.md §Migration Patterns: add Index::create() for all FK columns.`, and the section name has no trailing whitespace.

## Persistence impact

None. The output is in-memory and goes into the generated task text only, so no data migration is required.
