## Comment Content (as posted on ACME-500)

### Root Cause

The `plan-feature` skill's convention lookup extracts heading text from `CONVENTIONS.md`
using `line[3:]` — a fixed-offset slice that captures all characters after the `## `
prefix. This extraction does **not** strip trailing whitespace. When a heading line
carries trailing spaces (e.g., `## Migration Patterns  `), the extracted section name
becomes `"Migration Patterns  "` (with trailing spaces).

Downstream, the convention-aware task enrichment step performs an exact-match lookup
(`if convention_name in discovered_conventions`). Because the stored key has trailing
spaces and the lookup key does not, the match always fails — causing the convention to
be silently omitted from the task's Implementation Notes. No warning is emitted, so the
omission is invisible to the user.

### Affected Files

- **`plugins/sdlc-workflow/skills/plan-feature/SKILL.md`**
  - _Convention lookup section_: the `line[3:]` extraction that produces the section key
  - _Convention-aware task enrichment section_: the `if convention_name in discovered_conventions` comparison that fails due to the whitespace mismatch

### Suggested Approach

1. **Strip trailing whitespace at extraction time**: change the heading extraction
   instruction so that it trims trailing whitespace from the heading text immediately
   after the `## ` prefix is removed — i.e., apply `.strip()` (or equivalent) to
   `line[3:]`. This produces a canonical key `"Migration Patterns"` regardless of any
   trailing spaces in the source file.
2. **Add eval coverage**: add a `CONVENTIONS.md` fixture to the plan-feature eval suite
   that contains at least one heading with trailing whitespace, and assert that the
   generated task's Implementation Notes include the expected convention reference.
3. **No data migration required**: the defect affects future plan-feature invocations
   only. Previously created tasks that silently omitted a convention reference are
   point-in-time artifacts; no automated correction of existing Jira issues is needed.

### Reproducer Strategy

A test that verifies the fix should:

1. Set up a `CONVENTIONS.md` fixture with a heading line that has trailing whitespace:
   ```
   ## Migration Patterns  
   Add Index::create() for all FK columns.
   ```
2. Run `/plan-feature` on a feature that requires a database migration with foreign keys,
   using this fixture as the conventions source.
3. **Before the fix**: assert that the generated task's Implementation Notes do NOT
   contain `"Per CONVENTIONS.md §Migration Patterns"` (reproduces the bug).
4. **After the fix**: assert that the generated task's Implementation Notes DO contain:
   `"Per CONVENTIONS.md §Migration Patterns: add Index::create() for all FK columns."`

The existing fixture `evals/plan-feature/files/conventions-mock.md` should be
augmented (or a separate fixture created) to cover this trailing-whitespace edge case.
