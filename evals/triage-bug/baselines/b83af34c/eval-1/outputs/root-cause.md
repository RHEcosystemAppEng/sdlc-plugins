## Root Cause

The plan-feature skill's convention conformance analysis extracts CONVENTIONS.md
heading names using `line[3:]`, which preserves trailing whitespace from the source
file. When a heading line contains trailing spaces (e.g., `## Migration Patterns  `),
the extracted key becomes `"Migration Patterns  "` instead of `"Migration Patterns"`.
The subsequent convention matching step performs an exact string comparison, which
fails because the lookup key does not include trailing whitespace. The convention
is silently dropped with no warning or error.

## Affected Files

- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- convention conformance
  analysis section (heading extraction at `line[3:]`)
- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- convention-aware task
  enrichment section (exact-match lookup `if convention_name in discovered_conventions`)

## Suggested Approach

1. Add `.strip()` to the heading extraction to normalize whitespace:
   change `section_name = line[3:]` to `section_name = line[3:].strip()`.
2. Consider also stripping convention name lookup keys for defense-in-depth.
3. Add a warning log when a convention section referenced during task enrichment
   is not found in the parsed conventions, to prevent silent failures in the future.

## Reproducer Strategy

Create a test fixture (CONVENTIONS.md) with trailing whitespace on a heading line,
run the convention parsing logic, and assert that the convention is correctly matched
and included in the generated task's Implementation Notes despite the trailing
whitespace. The test should:

1. Set up a CONVENTIONS.md with `## Migration Patterns  ` (trailing spaces on heading)
2. Invoke the convention conformance analysis
3. Assert that the output includes the convention reference:
   `Per CONVENTIONS.md Migration Patterns: add Index::create() for all FK columns.`
