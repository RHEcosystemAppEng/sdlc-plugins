# Step 4 -- Root Cause Analysis

## Root Cause Determination

### What is broken

The dark mode preference toggle in the Settings > Appearance panel updates only the
in-memory application state. There is no persistence mechanism to save the user's
theme preference to durable storage (such as localStorage, a cookie, or a server-side
user preferences endpoint).

### Why it is broken

The settings panel toggle handler modifies a runtime state variable to switch between
light and dark mode, but no code path writes this preference to any persistent storage.
When the browser session ends, the in-memory state is discarded and the application
falls back to its default theme (light mode) on the next load.

### Where it is broken

- **Settings panel toggle handler**: the event handler that processes the dark mode
  toggle change -- it updates the theme in memory but does not persist the value.
- **Application initialization**: the startup/bootstrap code that loads the initial
  theme -- it does not check for a previously saved preference in persistent storage
  and defaults to light mode.

### How to verify the fix (Reproducer Strategy)

A reproducer test should:

1. Simulate enabling dark mode via the settings panel toggle
2. Verify the preference is written to persistent storage (e.g., localStorage)
3. Simulate a new browser session (clear in-memory state, re-initialize the app)
4. Assert that the application loads in dark mode by reading the persisted preference
5. Assert that the dark mode toggle reflects the ON state

The test should fail before the fix (no persistence write, app defaults to light mode)
and pass after the fix (preference is persisted and restored).

## Root Cause Comment (posted to ACME-511)

**Root Cause**: The dark mode preference is stored only in volatile application state.
No code path persists the preference to durable storage (localStorage, cookie, or
server-side API). On browser restart, the in-memory state is lost and the application
defaults to light mode.

**Affected Files**:
- Settings panel toggle handler (preference state update without persistence write)
- Application initialization/bootstrap (no check for saved theme preference)

**Suggested Approach**: Add a persistence layer for theme preferences -- write the
preference to localStorage (or equivalent) when toggled, and read it during
application initialization to restore the user's last selected theme before rendering.

**Reproducer Strategy**: Write a test that toggles dark mode, simulates a session
restart (clear memory state, re-initialize), and asserts the application loads in
dark mode with the toggle in the ON position.
