## Root Cause

The plan-feature skill's convention heading extraction uses `line[3:]` to parse
`## ` headings from `CONVENTIONS.md`, but does not strip trailing whitespace from
the extracted text. When a heading line contains trailing spaces (e.g.,
`## Migration Patterns  `), the extracted section name becomes
`"Migration Patterns  "` (with trailing spaces). Subsequent exact-match lookups
against the expected name `"Migration Patterns"` fail silently, causing the
convention to be omitted from the generated task with no warning or error.

## Affected Files

- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- convention heading
  extraction logic (`section_name = line[3:]` does not call `.strip()`)
- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- convention-aware task
  enrichment (`convention_name in discovered_conventions` fails due to key mismatch)

## Suggested Approach

Apply `.strip()` (or `.rstrip()`) to the extracted heading text so that trailing
whitespace is normalized before storing as a dictionary key:

```python
section_name = line[3:].strip()
```

This ensures that headings with trailing whitespace match the same key as headings
without it. Additionally, consider logging a warning when a convention heading
contains leading or trailing whitespace, to surface formatting issues in
`CONVENTIONS.md` files.

## Reproducer Strategy

1. Create a `CONVENTIONS.md` fixture with trailing whitespace on a heading
   (e.g., `## Migration Patterns  ` with two trailing spaces).
2. Run the plan-feature convention extraction against this fixture for a feature
   that should trigger the "Migration Patterns" convention.
3. **Assert (before fix)**: the generated task's Implementation Notes do NOT
   contain a reference to "Migration Patterns" -- confirming the bug.
4. **Assert (after fix)**: the generated task's Implementation Notes DO contain
   `Per CONVENTIONS.md Migration Patterns: ...` -- confirming the fix.
