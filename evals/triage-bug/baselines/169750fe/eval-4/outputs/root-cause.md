# Step 4 -- Root Cause Analysis: ACME-510

## Root Cause Determination

### What is broken

The `GET /api/v2/advisories` endpoint does not include `X-Total-Count` and `Link`
pagination headers in the HTTP response when the request includes date-range filter
parameters (`publishedAfter` and `publishedBefore`). The response body contains the
correct filtered advisories, but clients cannot determine total result count or
navigate pages.

### Why it is broken

The advisories endpoint handler has two query paths:

1. **Unfiltered path** (no date-range parameters): executes the standard query,
   computes total count, and calls the pagination header utility to set
   `X-Total-Count` and `Link` headers on the response.
2. **Filtered path** (with `publishedAfter`/`publishedBefore`): executes a
   date-range-filtered query that returns the correct result set, but **does not
   call the pagination header utility**. The filtered query path either:
   - Omits the total count query entirely (does not execute a `COUNT(*)` query
     alongside the filtered data query), or
   - Executes the count but fails to pass it to the pagination header utility.

This is a missing function call -- the filtered code path was added without
replicating the pagination header logic from the unfiltered path.

### Where it is broken

- **Primary defect**: The advisories endpoint handler (likely
  `src/api/v2/advisories.rs` or equivalent) -- the filtered branch does not invoke
  the pagination header utility after executing the date-range query.
- **Related code**: The pagination utility (likely `src/api/common/pagination.rs`
  or equivalent) and the filtered query function (likely `src/db/advisories.rs`
  or equivalent) are correct in isolation -- the issue is that they are not wired
  together for the filtered path.

### How to verify the fix

A reproducer test should:

1. Call `GET /api/v2/advisories?publishedAfter=2025-01-01&publishedBefore=2025-06-30&limit=10`
2. Assert that the response includes an `X-Total-Count` header with the correct
   total count of matching advisories
3. Assert that when more results exist than the limit, the response includes a
   `Link` header with `rel="next"`
4. Verify that the response body still contains the correct filtered results
   (regression guard)
