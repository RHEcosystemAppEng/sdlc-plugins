## Root Cause

The plan-feature skill's convention lookup extracts `CONVENTIONS.md` section headings using `line[3:]`, which slices the line after the `## ` prefix but does **not** strip trailing whitespace. When a heading line contains trailing spaces (e.g., `## Migration Patterns  `), the extracted section name becomes `"Migration Patterns  "` instead of `"Migration Patterns"`. The subsequent convention-aware task enrichment performs an exact-match lookup against the expected name (without trailing whitespace), which fails silently -- no warning is logged and the convention is simply omitted from the generated task description.

## Affected Files

- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- convention lookup loop where `section_name = line[3:]` should be `section_name = line[3:].strip()`
- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- convention-aware task enrichment that relies on exact-match `convention_name in discovered_conventions`

## Suggested Approach

Add a `.strip()` call to the heading extraction to normalize trailing whitespace:

```python
section_name = line[3:].strip()
```

This ensures the extracted section name matches regardless of trailing whitespace in the source `CONVENTIONS.md` file. No changes are needed to the task enrichment lookup since the keys in the conventions dictionary will now be properly normalized.
