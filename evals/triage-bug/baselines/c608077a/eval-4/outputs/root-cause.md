## What is broken

`GET /api/v2/advisories` leaves out the `X-Total-Count` and `Link` (`rel="next"`) pagination
headers when the request has date-range filter parameters (`publishedAfter` and/or
`publishedBefore`). The filtered response body is correct. Unfiltered requests emit the headers
correctly.

## Why it is broken

The filter itself works, because the body is correct. So the defect is in how the response is
built on the date-filtered path, not in the query predicate. The most likely cause is that the
date-range branch of the advisories listing builds its result without the pagination metadata
that the header-writing logic needs. For example, it returns a plain `Vec` of advisories instead
of the paginated result (items, total count, next-offset). It may also skip the total-count query
for the filtered query. With no total available, the header code emits neither `X-Total-Count`
nor `Link`.

A secondary possibility: the `Link` URL builder fails, or returns nothing, when it has to carry
the extra date query parameters, and the header code then drops both headers together.

## Where it is broken

- Repository: `acme-backend` (`/home/dev/repos/acme-backend`)
- Location: the advisories list endpoint handler or service, specifically the branch that handles
  `publishedAfter`/`publishedBefore`, plus the point where pagination headers are attached.
- **The exact file paths and symbols could not be confirmed** from the investigation inputs. A
  `Grep` for `published_after|publishedAfter` and `X-Total-Count` in `acme-backend` will find them.

## How to verify the fix

A reproducer integration test against `GET /api/v2/advisories`:
- Seed more advisories in the 2025-01-01..2025-06-30 window than the page limit (e.g. 15, with
  `limit=10`), plus some outside the window.
- Request `?publishedAfter=2025-01-01&publishedBefore=2025-06-30&limit=10`.
- Assert that `X-Total-Count` is present and equals the number of in-window advisories (15), and
  that `Link` is present with `rel="next"` and keeps the `publishedAfter`/`publishedBefore` params.
- Before the fix, the test fails because the headers are absent. After the fix, it passes.

## Persistence impact

None. The headers are computed per request, so no data migration is needed.
