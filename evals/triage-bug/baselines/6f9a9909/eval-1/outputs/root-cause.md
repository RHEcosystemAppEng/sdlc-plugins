## Root Cause Analysis

### What is broken

The plan-feature skill's convention heading extraction does not strip trailing whitespace from `CONVENTIONS.md` heading lines. The extraction logic uses `line[3:]` to capture the heading text after `## `, but this preserves any trailing spaces or tabs present on the line. For example, the heading `## Migration Patterns  ` (with trailing spaces) is extracted as `"Migration Patterns  "` rather than `"Migration Patterns"`.

### Where it is broken

The bug is in the plan-feature convention lookup logic in `plugins/sdlc-workflow/skills/plan-feature/SKILL.md`. Specifically, the heading extraction expression:

```python
section_name = line[3:]  # Does not strip trailing whitespace
```

This produces section name keys with trailing whitespace that fail the exact-match comparison in the downstream convention-aware task enrichment step:

```python
if convention_name in discovered_conventions:
    # This match fails because the key has trailing whitespace
```

Because no warning or error is logged when the match fails, the convention is silently dropped from the generated task description.

### How to verify the fix

1. Create a reproducer test with a `CONVENTIONS.md` fixture that includes trailing whitespace on one or more heading lines (e.g., `## Migration Patterns  ` with trailing spaces).
2. Run the plan-feature skill against a feature that should trigger the convention.
3. Assert that the generated task's Implementation Notes include the expected convention reference (`Per CONVENTIONS.md Migration Patterns: ...`), confirming that trailing whitespace on headings no longer causes silent convention loss.
