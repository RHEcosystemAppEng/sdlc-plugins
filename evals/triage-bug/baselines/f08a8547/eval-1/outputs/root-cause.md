## Root Cause

The plan-feature skill's CONVENTIONS.md parser extracts section headings using `line[3:]` without stripping trailing whitespace. When a heading line contains trailing spaces (e.g., `## Migration Patterns  `), the extracted section name retains those spaces (`"Migration Patterns  "`). The subsequent convention-matching step uses exact string comparison (`if convention_name in discovered_conventions`), which fails because the expected key `"Migration Patterns"` does not match the stored key `"Migration Patterns  "`. No warning is emitted on mismatch, so the convention is silently dropped from the generated task description.

## Affected Files

- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- convention conformance analysis section
  - Heading extraction: `section_name = line[3:]` (missing `.strip()`)
  - Convention matching: `if convention_name in discovered_conventions` (exact match, no normalization)

## Suggested Approach

1. Apply `.strip()` to the extracted heading text so that trailing (and leading) whitespace is normalized: `section_name = line[3:].strip()`
2. Consider also normalizing the lookup key in the convention matching step for defense-in-depth
3. Optionally, add a warning log when an expected convention is not found in the parsed conventions dictionary, so that similar issues surface instead of failing silently

## Reproducer Strategy

1. Create a test fixture `CONVENTIONS.md` with trailing whitespace on at least one heading (e.g., `## Migration Patterns  ` with two trailing spaces)
2. Run the plan-feature convention conformance analysis against this fixture
3. Assert that the convention IS included in the generated task's Implementation Notes (currently fails -- the convention is silently dropped)
4. After applying the fix (`.strip()`), the same test should pass
