# Step 4 -- Root Cause Analysis: ACME-511

## Root Cause Determination

### What is broken

The convention heading extraction logic in the plan-feature skill does not strip
trailing whitespace from section names parsed out of `CONVENTIONS.md`. When a heading
line contains trailing spaces (e.g., `## Migration Patterns  `), the extracted section
name retains those spaces. Subsequent exact-match lookups against expected convention
names fail because the stored key includes invisible trailing whitespace that the
lookup key does not.

### Why it is broken

The extraction code uses `line[3:]` to capture everything after the `## ` prefix, but
does not call `.strip()` on the result. Markdown headings commonly have trailing
whitespace (editors may add it, copy-paste may introduce it), and the code does not
account for this. The downstream convention matching uses `in` dictionary membership
testing, which requires exact key equality -- so `"Migration Patterns  "` does not
match `"Migration Patterns"`.

### Where it is broken

- **Primary defect**: `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- the
  convention heading extraction logic at `section_name = line[3:]`
- **Impact point**: `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- the
  convention-aware task enrichment logic at `if convention_name in discovered_conventions`
- **Missing test coverage**: `evals/plan-feature/files/conventions-mock.md` -- eval
  fixture does not include headings with trailing whitespace

### How to verify the fix

A reproducer test should:

1. Create a CONVENTIONS.md fixture with at least one heading that has trailing
   whitespace (e.g., `## Migration Patterns  `)
2. Run the convention heading extraction logic against it
3. Assert that the extracted section name is `"Migration Patterns"` (stripped),
   NOT `"Migration Patterns  "` (with trailing spaces)
4. Assert that the downstream convention matching succeeds when looking up
   `"Migration Patterns"` in the discovered conventions dictionary
