# Step 4 -- Root Cause Analysis

## Root Cause

The plan-feature skill's convention parser extracts CONVENTIONS.md section headings using
`line[3:]`, which captures the raw text after `## ` without stripping trailing whitespace.
When a heading line contains trailing spaces (e.g., `## Migration Patterns  `), the
extracted section name becomes `"Migration Patterns  "` (with trailing spaces). The
downstream convention-matching step uses exact string comparison
(`convention_name in discovered_conventions`), which fails because the lookup key
`"Migration Patterns"` does not equal the stored key `"Migration Patterns  "`. The
convention is silently dropped with no warning or error.

## Affected Files

- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- convention heading extraction
  (`line[3:]` without `.strip()`)
- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- convention-aware task enrichment
  (exact-match comparison `convention_name in discovered_conventions`)

## Suggested Approach

1. Add `.strip()` to the heading extraction: change `section_name = line[3:]` to
   `section_name = line[3:].strip()` to normalize heading text by removing leading and
   trailing whitespace.
2. Optionally, also `.strip()` the lookup key (`convention_name`) at the matching site for
   defense in depth.
3. Consider adding a warning log when a known/expected convention is not found in the
   discovered conventions dictionary, to prevent silent failures in the future.
