# Step 4 -- Root Cause Analysis: ACME-500

## Root Cause

The plan-feature skill's convention conformance analysis extracts CONVENTIONS.md
heading text using `line[3:]`, which captures everything after the `## ` prefix
including any trailing whitespace characters. When a heading line contains trailing
spaces (e.g., `## Migration Patterns  `), the extracted section name becomes
`"Migration Patterns  "` instead of `"Migration Patterns"`. The subsequent
convention lookup uses exact string matching (`if convention_name in discovered_conventions`),
which fails because the key with trailing spaces does not match the clean lookup key.
The convention is silently dropped with no warning or error logged.

## Affected Files

| File | Symbol/Location | Role |
|------|-----------------|------|
| `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` | Convention conformance analysis -- heading extraction (`section_name = line[3:]`) | Extracts heading names without stripping whitespace |
| `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` | Convention-aware task enrichment (`if convention_name in discovered_conventions`) | Performs exact-match lookup that fails on whitespace-padded keys |

## Suggested Approach

1. **Fix heading extraction**: Strip trailing whitespace from the extracted section name.
   Change `section_name = line[3:]` to `section_name = line[3:].strip()` (or equivalent
   whitespace-trimming operation) so that heading names are normalized regardless of
   trailing whitespace in the source file.

2. **Add warning for unmatched conventions** (defense in depth): When a convention name
   looked up during task enrichment is not found in the discovered conventions dictionary,
   log a warning message to alert the user that a convention was skipped. This prevents
   silent data loss in future edge cases.
