# Step 4 -- Root Cause Analysis: ACME-510

## Root Cause Determination

### What is broken

The `/api/v2/advisories` endpoint does not include `X-Total-Count` and `Link`
pagination headers in the HTTP response when date range filter parameters
(`publishedAfter`, `publishedBefore`) are used. The response body contains the
correct filtered results, but clients cannot determine total pages or navigate
to subsequent pages.

### Why it is broken

The advisories endpoint handler has two query paths: an unfiltered path and a
filtered path (for date range queries). The unfiltered path correctly invokes
the pagination helper, which executes a count query and generates the pagination
headers. The filtered path either:

1. Bypasses the pagination helper entirely, returning filtered results without
   computing the total count, or
2. Calls the pagination helper but does not pass the date range filter predicates
   to the count query, causing the count query to fail or return incorrect results,
   leading the helper to omit the headers.

The most likely cause is that the filtered query branch was added without updating
the pagination header generation logic to account for the filter predicates.

### Where it is broken

- **Primary**: The advisories endpoint handler (expected location:
  `src/api/v2/advisories.rs` or `src/handlers/advisories.rs`) -- the filtered
  query branch does not invoke or properly configure the pagination helper.
- **Secondary**: The pagination helper (expected location: `src/api/pagination.rs`
  or similar) may need to accept filter predicates as parameters for its count query.

### How to verify the fix

A reproducer test should:

1. Call `GET /api/v2/advisories?publishedAfter=2025-01-01&publishedBefore=2025-06-30&limit=10`
2. Assert that the response includes the `X-Total-Count` header with the correct
   total count of matching advisories
3. Assert that the response includes the `Link` header with `rel="next"` when more
   pages exist
4. Verify that the response body still contains the correct filtered results
5. Compare behavior with an unfiltered request to confirm consistency
