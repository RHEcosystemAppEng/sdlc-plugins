## Root Cause

The plan-feature skill's convention heading extraction uses `line[3:]` to extract
the section name after `## `, but does not strip trailing whitespace. When a
`CONVENTIONS.md` heading line contains trailing spaces (e.g., `## Migration Patterns  `),
the extracted key becomes `"Migration Patterns  "` instead of `"Migration Patterns"`.
The downstream convention-aware task enrichment performs an exact-match lookup against
the stored key, which fails silently -- no warning is logged, and the convention is
omitted from the generated task description.

## Affected Files

- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- convention heading extraction logic
  - Defect: `section_name = line[3:]` does not call `.strip()` on the extracted heading text
- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- convention-aware task enrichment
  - Failure: `if convention_name in discovered_conventions` exact match fails when key has trailing whitespace

## Suggested Approach

1. Add `.strip()` to the heading extraction: `section_name = line[3:].strip()`
2. This normalizes all heading names regardless of trailing whitespace in the source file.
3. No changes needed to the downstream matching logic -- it will work correctly once
   keys are normalized at extraction time.
4. Consider also logging a warning when a heading with trailing whitespace is detected,
   to aid future debugging.

## Reproducer Strategy

1. Create a test `CONVENTIONS.md` fixture with trailing whitespace on a section heading
   (e.g., `## Migration Patterns  ` with two trailing spaces).
2. Run the convention extraction logic against this fixture.
3. Assert that the extracted section name equals `"Migration Patterns"` (without trailing spaces).
4. Assert that the convention-aware task enrichment includes the convention in the
   generated output when the heading has trailing whitespace.
