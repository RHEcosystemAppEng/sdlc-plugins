## What is broken

`GET /api/v2/advisories` leaves out the `X-Total-Count` and `Link` (`rel="next"`) response headers whenever the date-range filters `publishedAfter` and/or `publishedBefore` are supplied. The filtered body is correct. Unfiltered requests get both headers.

## Why it is broken

The handler has a separate branch for date-range filtering, called `filterDateRange` in the report. That branch returns the filtered list of advisories directly, without the pagination metadata. Either it never runs the total-count query, or it returns a plain list instead of the paginated result type that the header-writing step uses. Because no total or next-page information reaches the response builder, both headers are skipped together. The most likely origin is that date-range filtering was added as its own query path, and nobody wired it into the existing pagination flow used by the default listing.
