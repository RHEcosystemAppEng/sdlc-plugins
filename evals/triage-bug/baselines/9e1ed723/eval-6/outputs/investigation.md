# Steps 2–3 – Reproduce/Trace and Codebase Investigation: ACME-500

## Step 2 – Reproduce / Trace

**Reproduction mode: code-path tracing.** The Steps to Reproduce call a skill
(`/plan-feature ACME-100`) and depend on a live Jira feature, so they cannot be run
read-only. Per the Step 2 guidance for skill/documentation bugs, I traced the code path instead.

Trace:

1. **Entry point**: `/plan-feature ACME-100` runs the plan-feature skill
   (`plugins/sdlc-workflow/skills/plan-feature/SKILL.md`).
2. **Convention conformance analysis** reads the target repo's `CONVENTIONS.md` and builds a
   map of section name to content:
   ```python
   for line in conventions_content.split('\n'):
       if line.startswith('## '):
           section_name = line[3:]          # no .strip()
           conventions[section_name] = current_section_content
   ```
   With the input `## Migration Patterns  `, the map key becomes `"Migration Patterns  "`
   (two trailing spaces).
3. **Convention-aware task enrichment** looks up conventions by exact name:
   ```python
   if convention_name in discovered_conventions:
       notes.append(f"Per CONVENTIONS.md §{convention_name}: {action}")
   ```
   The lookup for `"Migration Patterns"` misses the key `"Migration Patterns  "`, and no
   else-branch or warning exists.
4. **Divergence point**: the heading extraction `line[3:]` in step 2. The silent drop in
   step 3 then hides the failure, which matches the Actual Result (no note, no warning).

Outcome: the trace confirms the reported behavior.

## Step 3 – Codebase Investigation

- Code Intelligence: no Serena servers are configured, so I fell back to Read/Grep/Glob

### Affected files and symbols

| File | Location / symbol | Role in bug |
|---|---|---|
| `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` | Convention conformance analysis: heading parse loop (`section_name = line[3:]`) | **Defect.** Heading text is not normalized, so trailing whitespace stays in the key |
| `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` | Convention-aware task enrichment: `if convention_name in discovered_conventions` | Consumer. The exact-match lookup fails, and the miss is silent (no warning) |

### Impact analysis
- Every convention whose `CONVENTIONS.md` heading ends in whitespace (spaces or tabs) is affected,
  not only Migration Patterns. A trailing `\r` from CRLF files would hit the same path,
  because `split('\n')` leaves `\r` on the line.
- Downstream: tasks generated by plan-feature leave out convention guidance, so
  implement-task may produce code that breaks repository conventions (for example, a missing
  `Index::create()` for FK columns).

### Existing tests and patterns
- `evals/plan-feature/files/conventions-mock.md`: the existing plan-feature conventions eval
  fixture. Its headings have **no** trailing whitespace, so this edge case is not covered.
  This is the pattern to copy for the reproducer (a fixture variant plus an eval entry in
  `evals/plan-feature/evals.json`).

### Reuse candidates
- Python `str.strip()` / `str.rstrip()` normalization at the extraction point. No new helper
  is needed.
- The existing fixture `evals/plan-feature/files/conventions-mock.md` can be the template
  for the new trailing-whitespace fixture.

### CONVENTIONS.md lookup
- The repository has **no** `CONVENTIONS.md` at its root, so no repo-specific conventions apply.

### Persistence-impact analysis
- The buggy output (convention section names and the generated Implementation Notes) is
  produced in memory during each plan-feature run and goes into newly generated Jira task text.
- **No database persistence boundary** exists (no insert/update/ORM write of this value).
  **No data migration is needed.** Tasks that were already generated with missing conventions
  are outside the scope of a code fix. They can be re-planned manually if needed.

### Decomposition Guard (Step 6) check
There is one root cause (heading names are not normalized at extraction). It shows up as a
silent miss at the lookup site. Adding a warning on a miss is part of the same fix, not an
independent defect, so **no decomposition is needed** and a single Task is appropriate.
