## What happens for each choice

### 1. Keep
- Sub-steps 4.5.2 through 4.5.6 are skipped.
- No change is made to the `versions` field, and no gap comment is posted.
- Triage goes straight to Step 5 (Generate Task).

### 2. Replace
- 4.5.2 (extract from description): the `### **Environment / Version**` section is missing
  from ACME-500's description (see bug-parsing.md), so no version can be extracted from the
  description.
- 4.5.3: available versions are discovered with
  `jira.getJiraIssueTypeMetaWithFields(projectIdOrKey: "ACME", issueTypeId: "10020")`, and
  `versions.allowedValues` (id, name, released, releaseDate) is read from the response. I show
  that list to the user (no Jira call was made in this eval, so no real version list is available).
- 4.5.4 and 4.5.5: no extracted text exists to match, so the user picks the replacement from the
  available-versions list or types one in. I then confirm and call:
  ```
  jira.edit_issue("ACME-500", fields={"versions": [{"id": "<selected-version-id>"}]})
  ```
  The version ID comes from 4.5.3 and is never hardcoded.
- 4.5.6: if the user cannot choose a valid version, I post this comment on ACME-500:
  > Affects Version could not be determined from the bug description — please set manually.
  >
  > ---
  > This comment was AI-generated by [sdlc-workflow/triage-bug](https://github.com/RHEcosystemAppEng/sdlc-plugins) v0.14.0.

### 3. Augment
- Same discovery and selection flow as Replace (4.5.3–4.5.5).
- The new version(s) are **merged** with the existing value instead of replacing it:
  ```
  jira.edit_issue("ACME-500", fields={"versions": [
    {"id": "<id-of-existing-0.9.0>"},
    {"id": "<additional-version-id>"}
  ]})
  ```
