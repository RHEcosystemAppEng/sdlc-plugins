# Step 4 – Root Cause Analysis: ACME-511

**Confidence: LOW / provisional.** The provided repository context does not include the
code that implements the dark mode toggle or preference persistence (it describes an
unrelated bug, ACME-500). The analysis below comes from the bug's symptoms and the expected
architecture of a persisted UI preference. It must be confirmed against the real source
before or during implementation.

## 1. What is broken

The user's dark mode preference does not survive a full browser restart. After
reopening, the app starts in light mode and the toggle shows OFF.

## 2. Why it is broken (most likely causes, in order)

1. **Preference not written to durable storage.** The toggle handler updates only
   in-memory state (component/store state) or `sessionStorage`. Both are cleared when the
   browser closes.
2. **Preference written but not read on startup.** The app bootstrap/theme provider
   initializes the theme to a hardcoded `light` default and never reads the stored value
   (or reads it after the initial render and then overwrites it with the default).
3. **Server-side preference not saved or not loaded (if preferences live in acme-backend).**
   The settings save call is missing or fails silently, or the user-profile/preferences
   response used on load leaves out the theme field.

All three are one defect area: the theme preference is not round-tripped through
persistent storage. They are alternative explanations for one root cause, not independent
issues, so the Decomposition Guard does not apply.

## 3. Where it is broken

- **Not determined.** No files or symbols for the theme toggle, theme provider, or
  preferences storage/API appeared in the provided repository context.
- The only registered repository is `acme-backend` (Rust backend). If the theme preference
  is client-side only, the fix belongs in a frontend repository that is not in the
  Repository Registry.

## 4. How to verify the fix (reproducer strategy)

A reproducer test should model a "new browser session":

- Arrange: initialize the app/theme state with nothing stored.
- Act: set dark mode ON through the same code path the Settings > Appearance toggle uses.
- Simulate a restart: tear down app state, clear in-memory and session-scoped state, and
  keep only durable storage (`localStorage`/cookie, or the backend preferences record).
- Re-initialize the app.
- Assert: the theme resolves to `dark` and the toggle reads ON.
  - Before fix: the theme resolves to `light` / toggle OFF (matches the Actual Result).
  - After fix: the theme resolves to `dark` / toggle ON (matches the Expected Result).

If preferences are server-side, add a backend test: save the theme preference for a user,
fetch the user's preferences in a new request, and assert the theme is `dark`.
