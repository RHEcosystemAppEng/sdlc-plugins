## Root cause determination

1. **What is broken:** `GET /api/v2/advisories` leaves out the `X-Total-Count` and `Link` pagination
   headers when the request includes the `publishedAfter` / `publishedBefore` date-range filters. The response body is correct.
2. **Why it is broken (inferred):** the date-range path in the advisories handler, or the service function it calls,
   builds its response differently from the unfiltered path. The likely cause is one of these:
   (a) the filtered path returns a plain list of results instead of the paginated wrapper that the
   header-emitting code expects, or (b) the filtered path skips the total-count query, so no total is available and
   header generation is silently skipped. Both fit the symptoms: correct body, both headers missing, unfiltered requests fine.
3. **Where it is broken:** in `acme-backend`, the `/api/v2/advisories` handler and its date-filter branch.
   **The exact files and symbols were not identified.** The provided repository context does not cover this endpoint.
4. **How to verify the fix:** an integration test that calls
   `GET /api/v2/advisories?publishedAfter=2025-01-01&publishedBefore=2025-06-30&limit=10` against a dataset
   with more than 10 matching advisories. It asserts that `X-Total-Count` equals the number of matching advisories (not the page size) and that
   `Link` contains `rel="next"`. Before the fix it fails because the headers are absent. After the fix it passes.
