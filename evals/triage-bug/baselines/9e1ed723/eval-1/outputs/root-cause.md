## Root Cause Analysis

### Root Cause
plan-feature's convention conformance analysis builds its convention map from `CONVENTIONS.md`
by taking the raw text after `## ` on each heading line (`section_name = line[3:]`) without
normalizing whitespace. A heading such as `## Migration Patterns  ` is therefore stored under the
key `"Migration Patterns  "`. The later convention-aware task enrichment step performs an exact
membership check (`if convention_name in discovered_conventions:`) using the clean name
`"Migration Patterns"`, which fails. Because there is no `else` branch, the miss produces no
warning and the convention is silently omitted from the generated task's Implementation Notes.

- **What**: convention lookup misses headings with trailing whitespace.
- **Why**: heading keys are not trimmed at extraction; lookup is exact-match with no miss diagnostic.
- **Where**: `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` (two steps, one root cause).

### Affected Files
- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` — Convention conformance analysis:
  heading extraction `section_name = line[3:]` (defect origin)
- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` — Convention-aware task enrichment:
  `if convention_name in discovered_conventions:` (where the failure manifests silently)

### Suggested Approach
1. Normalize heading text at extraction time — trim trailing (and leading) whitespace, including
   tabs and `\r` from CRLF line endings — so stored keys match canonical section names.
2. Optionally make the enrichment lookup tolerant of whitespace as defense in depth.
3. Surface a warning when an expected/relevant convention section cannot be matched, instead of
   silently dropping it.

### Reproducer Strategy
- Add a plan-feature eval fixture (variant of `evals/plan-feature/files/conventions-mock.md`)
  whose `## Migration Patterns  ` heading has trailing whitespace and whose body says
  `Add Index::create() for all FK columns.`
- Add an eval case that plans a feature requiring a DB migration with foreign keys and asserts the
  generated task's Implementation Notes contain
  `Per CONVENTIONS.md §Migration Patterns: add Index::create() for all FK columns`.
- Before the fix the assertion fails (convention absent); after the fix it passes.
