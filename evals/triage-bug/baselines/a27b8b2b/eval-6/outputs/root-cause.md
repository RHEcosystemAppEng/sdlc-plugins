# Step 4 -- Root Cause Analysis: ACME-500

## Root Cause

The plan-feature skill's convention heading extraction uses `line[3:]` to parse `## ` headings from `CONVENTIONS.md`, but does not strip trailing whitespace from the extracted section name. When a heading line contains trailing spaces (e.g., `## Migration Patterns  `), the extracted key becomes `"Migration Patterns  "` instead of `"Migration Patterns"`. The subsequent convention-aware task enrichment uses exact-match comparison (`convention_name in discovered_conventions`), which fails because the lookup key lacks the trailing whitespace. The convention is silently dropped with no warning or error.

### What is broken

The heading extraction logic in the plan-feature skill's convention conformance analysis produces dictionary keys that include trailing whitespace from the source file. The exact-match convention lookup then fails to find these keys, causing valid conventions to be silently omitted from generated task descriptions.

### Why it is broken

The `line[3:]` slice operation extracts everything after the `## ` prefix, including any trailing whitespace characters. No `.strip()` or `.rstrip()` call is applied to normalize the extracted heading text. This is a classic string-trimming oversight.

- **File**: `plugins/sdlc-workflow/skills/plan-feature/SKILL.md`
- **Location 1**: Convention heading extraction loop -- `section_name = line[3:]`
- **Location 2**: Convention matching -- `if convention_name in discovered_conventions`
