# Step 4 -- Root Cause Analysis

## Root Cause

The dark mode preference fails to persist across browser sessions because the preference
key extraction logic does not strip trailing whitespace. When the setting is stored, the
key includes trailing whitespace (e.g., `"Dark Mode  "` instead of `"Dark Mode"`). On
subsequent page loads, the lookup uses the clean key `"Dark Mode"`, which does not match
the stored key with trailing whitespace. As a result, the preference lookup returns no
match and the application defaults to light mode.

This is the same class of defect found in the convention heading extraction at
`plugins/sdlc-workflow/skills/plan-feature/SKILL.md`, where `line[3:]` preserves
trailing whitespace from heading lines, causing exact-match comparison failures downstream.

## Affected Files

- `plugins/sdlc-workflow/skills/plan-feature/SKILL.md` -- heading extraction logic
  at `line[3:]` does not strip trailing whitespace
- Convention-aware task enrichment in the same file -- exact-match lookup on
  `convention_name` fails against whitespace-padded keys

## Suggested Approach

Apply `.strip()` to the extracted heading text to normalize whitespace before storing
it as a key:

```python
section_name = line[3:].strip()
```

This ensures that keys are consistently trimmed regardless of trailing whitespace in
the source content, and downstream exact-match comparisons will succeed.
